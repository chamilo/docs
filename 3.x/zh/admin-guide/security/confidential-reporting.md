# 保密举报

Chamilo 提供可选的**保密举报**工作流，用于向授权调查人员提交对另一用户的关切。这并非普通的支持工单工具，也不是公开讨论论坛。

## 启用该功能

打开**管理 > 配置设置 > 安全**，并配置以下项：

| 设置 | 默认值 | 用途 |
|---|---|---|
| `security.confidential_reporting_enabled` | `false` | 启用保密举报工作流 |
| `security.confidential_reporting_min_reporters` | `2` | 调查对调查人员可见之前所需的不同举报人最低数量（2–10） |
| `security.confidential_reporting_attachments_enabled` | `true` | 允许附加证据 |
| `security.confidential_reporting_notifications_enabled` | `false` | 为符合条件的调查显示内部指示（不发送电子邮件） |

部署时还要求服务器上的保密举报加密与私有存储已就绪。Chamilo 使用 PHP Sodium 加密函数以及一把私有加密密钥；**请安全保管并备份该密钥**。丢失密钥可能导致已存储的举报无法读取。请勿将密钥复制到 Git 仓库中。在确认私有密钥存储以及所需的数据库迁移均已正常运行之前，请勿启用该功能。

## 提交举报

1. 直接登录 Chamilo，并打开**保密举报**（在门户已启用该功能时）。
2. 选择相关人员，输入主题并描述事件。
3. 若已启用附件，可添加证据。
4. 决定调查人员是否可以查看您在此特定举报中的**姓名和电子邮件**。该授权可在之后撤回。
5. 发送举报。使用**我的保密举报**跟踪案件，并与调查人员交换消息。

默认情况下，举报人的身份**不会向调查人员显示**。这是一项保密控制措施，并非对系统运营者绝对匿名的承诺。

## 调查权限与阈值

调查需要专用的 `welfare:investigate` 权限，以及符合条件的管理员或人力资源角色。仅当针对同一对象的**不同举报人**数量达到所配置的数量后，案件才可供调查。调查人员不能调查关于其本人的举报。人力资源访问权限仅限于人力资源经理所关注的用户。

调查人员通过**保密调查**查看符合条件的案件、审阅证据并交换消息。未达阈值或未获授权的案件不会通过调查 API 暴露。管理层面的**身份模拟**不会提供对保密举报的访问权限。

## 隐私与运营注意事项

举报及所附证据包含敏感个人数据。应限制调查人员权限、限制备份访问、制定适当的组织保留策略，并使用相互独立的举报人、对象与调查人员账户测试该工作流。避免将完整举报复制到技术日志或问题跟踪系统中。
