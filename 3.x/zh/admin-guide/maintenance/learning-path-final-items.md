# 完成卡住的学习路径最终项

学习路径的最后一步——承载证书与技能区块的“恭喜”页面——只有在学习者实际打开后才会被计为完成。若学习者完成了其余所有步骤，却从未点击进入该最后一页，进度会永远停留在略低于 100% 的状态；而成就证书资格（以及技能授予）以学习路径达到 100% 为前提，因此他们无法获得本已应得的证书或技能。

```bash
php bin/console chamilo:learning-path:complete-final-items [options]
```

对于平台上最后一步类型为 **Final item** 的每条学习路径，该命令会检查每一次进行中的尝试（低于 100%）且已完成其余所有步骤的学习者——涵盖复用该学习路径的每一门课程和每一个会话。若满足条件，它会为这些学习者完成最终项，效果与他们亲自打开该页面完全相同：记录相同的项目查看、执行相同的进度重新计算，并触发真实访问时同样会发生的证书生成与技能授予。

与 `chamilo:gradebook:process-achievement-certificates`（参见 [成就证书](achievement-certificates.md)）一样，它以有界批次运行，支持试运行，并且在中断后可以安全恢复——最终项已完成的学习者在后续运行中绝不会被再次处理。

## 选项

| Option                 | Purpose                                                                                                            |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `--dry-run`             | 评估并报告，但不完成任何内容。请始终先运行此选项。                                           |
| `--sender-id=<id>`      | 有效的平台管理员 ID，在完成最终项触发证书生成或技能授予时用作资源创建者。真实（非试运行）执行时必填。 |
| `--limit=<n>`           | 单次运行中完成（或在试运行中报告）的最终项最大数量。`0` = 无限制。默认 `500`。              |
| `--scan-limit=<n>`      | 单次运行中扫描的学习者进度记录最大数量，涵盖所有学习路径。`0` = 无限制。默认 `5000`。 |
| `--batch-size=<n>`      | 在单条学习路径内，每批从数据库加载的学习者进度记录数。默认 `50`。                       |
| `--lp-batch-size=<n>`   | 每批从数据库加载的学习路径数。默认 `50`。                                                            |
| `--after-lp-id=<id>`    | 从此学习路径 ID 之后继续扫描。                                                                       |

## 示例

先对整个平台进行试运行，查看哪些学习者会被完成：

```bash
php bin/console chamilo:learning-path:complete-final-items --dry-run
```

真实运行，以 ID 为 1 的管理员作为资源创建者：

```bash
php bin/console chamilo:learning-path:complete-final-items --sender-id=1
```

在学习路径 480 之后恢复一次被中断的运行：

```bash
php bin/console chamilo:learning-path:complete-final-items --sender-id=1 --after-lp-id=480
```

## 退出代码

若在真实运行中至少有一个最终项实际未能完成，该命令将以失败状态退出——摘要表会列出学习路径、学习者及原因；应用程序日志中包含完整异常。被正确排除的学习者（最终项已完成，或另有步骤仍未完成）不算错误，也绝不会导致失败退出代码。

## 完成后的成绩册分数

成绩册表格中为学习路径显示的分数从不存储——它在每次页面加载时根据学习者的当前进度实时计算，因此会立即反映 100%，无需额外步骤。

若学习者在达到 100% 之前已存在**证书**（其中已写入较早、较低的分数），则只有在本命令完成其最终项时证书重新生成本身成功，已存储的分数和渲染后的 HTML 才会被刷新——这与真实访问所触发的调用相同。若证书生成因任何原因失败（常见原因见 [成就证书](achievement-certificates.md)，例如文件存储权限），学习者的进度仍会正确达到 100%，成绩册表格也会显示该进度——只是其证书仍显示旧分数；由于该命令绝不会再次处理已达 100% 的学习者，后续运行不会重试。请在根本问题修复后，手动重新生成该证书（证书列表中的 **Generate** 操作）。

`--sender-id` 的存在正是为了避免该失败的一个常见原因：在真实请求之外完成最终项时，没有已登录用户可供证书资源记录为创建者，缺少创建者时生成会直接失败。
