# 访问 URL

访问 URL 允许单一 Chamilo 安装同时为多个相互独立的门户提供服务。

该工具也可从管理仪表板的 [平台](../platform/README.md) 区块进入，对应项为 **配置多个访问 URL**。


## 使用场景

* **多租户部署** — 在同一台服务器上为不同组织托管各自独立的培训门户
* **部门门户** — 为每个部门提供带有独立品牌的门户（例如 `hr.training.company.com`、`it.training.company.com`）
* **区域门户** — 为不同地区或语言提供独立门户

## 工作原理

每个访问 URL 都是同一 Chamilo 安装的独立入口：

* 用户可被分配到一个或多个访问 URL
* 课程和学期（session）归属于特定访问 URL
* 平台设置可按访问 URL 进行定制
* 品牌形象与主题可按 URL 不同
* 某一门户上的用户无法看到另一门户上的用户或课程（除非明确共享）

## 配置

### 启用多 URL

必须在 Chamilo 配置中启用多 URL（通常在环境设置中）。这一般在初始安装时完成。

### 创建访问 URL

1. 从管理面板进入 **访问 URL**
2. 点击 **添加 URL**
3. 输入 URL（例如 `https://portal2.yoursite.com`）及描述
4. 可选择 **父级 URL**，将此 URL 嵌套在另一 URL 之下 — 参见下方 [URL 层级](#url-hierarchy)
5. 保存

### 分配用户与课程

* **用户** — 将用户分配到特定访问 URL。一名用户可属于多个 URL。
* **课程** — 将课程分配到特定访问 URL
* **学期** — 将学期分配到特定访问 URL

### 按 URL 的设置

每个访问 URL 可拥有各自的：

* **配色主题** — 不同的视觉品牌
* **平台名称与徽标** — 自定义身份标识
* **设置覆盖** — 部分平台设置可按 URL 定制

## URL 层级

访问 URL 可组织为父/子树结构，而非扁平列表。创建或编辑 URL 时，不受限制的全局管理员（参见下方 [子树管理员](#subtree-administrators)）可将任意其他 URL 选为其 **父级 URL**：

![编辑 URL 对话框中父级 URL 下拉列表已展开，列出可作为父级的其他访问 URL](/.gitbook/assets/admin-access-url-parent-select.png)

* 下拉列表不会提供正在编辑的 URL 或其任何后代作为可选父级 — 这可防止形成环。无论界面显示如何，后端都会再次校验。
* 若创建 URL 时未选择父级，则默认使用 **仅登录 URL**（若存在，参见上方 [按 URL 的设置](#per-url-settings)），否则使用第一个访问 URL — 与该功能出现之前的默认行为相同。
* 一棵树中最顶层、没有父级的 URL 即为该树的 **根**。单一 Chamilo 安装可托管多棵相互独立的树。

凡列出访问 URL 之处 — 多 URL 仪表板与访问 URL 管理页 — 树结构通过缩进展示：父级紧随其后为其子级（同级按字母排序），而不再使用单独的“父级”列：

![访问 URL 列表显示一个根 URL 及其两个子 URL，其中一个子 URL 还有自己的子 URL，通过缩进体现层级](/.gitbook/assets/admin-access-url-hierarchy-list.png)

## 子树管理员

URL 层级还决定 [全局管理员](../users/user-roles.md) 可管理的范围：

* 注册在某棵树 **根** URL 上的管理员为 **不受限制**：他们管理每一个访问 URL，与该功能出现之前完全相同。
* 仅注册在 **非根** URL 上的管理员为 **受限范围**：多 URL 与访问 URL 页面仅显示该 URL 及其后代，且多 URL 仪表板上的登录图表显示为“登录（您的 URL）”而非“登录（全部 URL 合计）”。

无论范围如何，以下操作仍仅保留给 **不受限制** 的全局管理员 — 受限管理员即使针对其自身子树内的 URL 也不得执行：

* 创建新的访问 URL
* 编辑访问 URL 自身的 URL、描述或父级
* 启用或停用访问 URL
* 删除访问 URL（整个安装的根 URL 任何人永远不可删除）
* 将自己一次性注册到每一个访问 URL

受限管理员仍可管理分配给其 subt 树内 URL 的一切 — 用户、课程、学期、品牌与设置 — 只是不能管理访问 URL 条目本身。

## 提示

* **尽早决策** — 若选择多 URL 配置，应在 Chamilo 项目启动之初就确定，因为这要求第一个 URL 尽量不放置内容。事后再启用多 URL 会更加困难（需要手动修改数据库）。
* **规划 URL 结构** — 在创建访问 URL 之前先确定 URL 方案，因为日后更改 URL 会影响所有现有链接和书签
* **DNS 配置** — 每个访问 URL 都必须解析到同一台 Chamilo 服务器。请相应配置 DNS 记录。
* **全局管理员** — 使用全局管理员角色跨所有访问 URL 进行管理。若只需将某一分支的管理权限委派出去，请在非根 URL 上注册该管理员 — 参见 [子树管理员](#subtree-administrators)
