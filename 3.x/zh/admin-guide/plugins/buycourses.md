# BuyCourses：付款与周期性服务

**BuyCourses** 插件用于销售课程与学习期次的访问权限，并可提供付费服务。可用的付款方式取决于本安装已配置的支付网关。

## 付款配置

打开 **管理 > 插件 > BuyCourses**，进入其付款配置区域。网关凭据应保存在服务器上，而不是放在面向学习者的页面中。Stripe 与 PayPal 等现有方式可继续独立于 BTCPay Server 运行。

### BTCPay Server（课程与学习期次购买）

该插件还支持通过 **BTCPay Server** 购买课程与学习期次：

1. 在 BuyCourses 配置中启用 BTCPay 付款方式。
2. 设置 BTCPay 的 **Server URL**、**Store ID**、**Greenfield API key** 与 **webhook secret**。
3. 使用付款配置中的**连接测试**，确认可访问 Greenfield API。
4. 在 BTCPay 端配置 webhook，使用插件显示的 webhook URL 以及相同的密钥。
5. 在向学习者提供此选项之前，先完成一笔小额测试购买。

购买者会被重定向到 BTCPay 托管的结账页面。Chamilo 会验证 webhook 签名，并再次获取发票，以校验**商店、金额、货币与订单详情**，然后才将订单标记为已付款并为购买者注册。浏览器返回可以补齐遗漏或延迟的 webhook。重复通知不会造成重复履约。

仅已验证的已结算付款（包括已接受的超额付款，以及管理员明确标记为已结算的发票）才会授予访问权限。**部分付款、逾期付款、已过期或无效的付款不得视为已自动履约**；例外付款需要人工审核。

**现有安装：** 运行一次该插件的更新过程，以创建 `plugin_buycourses_btcpay_account`。管理员可以打开 `/plugin/BuyCourses/update.php`，或保存 BTCPay 付款配置，这也会确保插件数据表存在。此更新仅针对 BuyCourses，并非全局数据库迁移。

此处**未**将 BTCPay 记录为周期性服务网关；不要假定它实现了与 Stripe/PayPal 类似的自动订阅续订。

## 周期性服务生命周期

学习者可以使用**我的服务**查看其有效的周期性服务以及购买/付款历史。对于支持自动续订的服务：

* 每次续订付款都有各自的历史记录与收据。
* 取消续订可阻止后续扣款，但已付款的服务在当前已付周期到期前仍可访问。
* 管理员也可以从**服务销售报表**中取消续订。
* 处于有效、待处理或其他仍在进行中的周期性订阅会受到保护，以免重复购买。
* 已过期或已完全取消的服务可以再次购买。

**购买历史**与**付款历史**是分开的：一次服务购买可能对应多笔续订付款。不要将续订付款推断为第二次购买。

## 服务销售付款合计

在管理员的**服务销售报表**中，有两列用于区分原始订单金额与随时间收取的付款：

* **最近付款**显示该服务销售最近一次已记录的成功付款日期。若没有可用的付款日期，报表显示短横线。
* **已收取总额**显示最初收取的购买金额加上已记录的成功续订金额，并以该服务的货币格式化。它并不等于单个计费周期的价格。

该计算使用服务销售审计历史，避免重复计入续订事件，并计入初始 Stripe 订阅扣款且不重复计算。对于例外付款或退款情形，请将报表与支付提供商核对；所示金额并非网关打款金额，也不是单独的退款账本。

## 历史 Stripe 订阅

对于较旧的周期性服务，若其续订交易未完整记录在插件审计日志中，BuyCourses 可以核对 Stripe 发票历史。**我的服务**视图与服务销售报表可以刷新这些记录，并更新本地已知的已付周期与合计。管理员应对照 Stripe 核实例外的付款历史差异，而不是直接编辑销售记录。

## 筛选销售报表

**课程与学习期次销售报表**可按订单状态、用户、日期范围或电子邮件筛选。可选的产品筛选器可按产品类型与产品名称缩小结果范围。**服务销售报表**支持状态筛选，以及用户/电子邮件/姓名/订单参考号搜索和服务名称搜索。在导出或核对销售数据之前，请检查当前生效的筛选条件；这两个报表界面的筛选控件并不相同。

参见 [BuyCourses 销售筛选器 PR #9387](https://github.com/chamilo/chamilo-lms/pull/9387)。

## 与订阅关联的课程生命周期及删除保护

BuyCourses 可根据付费状态的变化，关闭、隐藏并重新激活与周期性服务订阅关联的课程。在服务的 **Subscription behavior JSON** 中，`hide_after_days` 指定课程关闭后、隐藏前的延迟天数（默认 30 天），而 `delete_after_days` 指定隐藏后、永久删除前的延迟天数。删除默认处于禁用状态（`null`）；仅当该值为正数时，课程才具备删除资格。

管理员可在 `/admin/buycourses/course-lifecycle` 查看符合条件、待处理及被阻止的课程。该界面支持非破坏性模拟，以及每次执行仅针对**一门符合条件的课程**进行定向删除，并须经明确确认。命令行处理器 `chamilo:buycourses:process-recurring-subscriptions` 亦支持 `--dry-run`、`--delete-expired` 与 `--max-deletions`（1–25）。若未使用 `--delete-expired`，则不会永久删除课程。

**永久删除具有破坏性。** 请保留备份，并先使用可丢弃的课程进行测试。资格检查会保护正在销售的课程、与会话关联的课程以及所有权不一致的情况；在多访问 URL 安装中，自动删除会被阻止。在生产环境中安排破坏性清理之前，请审查并发的续订与删除行为。参见 [订阅课程生命周期 PR #9442](https://github.com/chamilo/chamilo-lms/pull/9442)。

## 运行检查

升级后，请测试一次完整的课程购买、一次已售出的会话购买（如有销售）、一次延迟或重放的 webhook、已过期及部分支付的 BTCPay 发票、一次自动续订，以及取消后访问权限持续至已付费周期结束的情况。请勿将凭据和 webhook 密钥写入截图、日志及支持工单。

## 支付加固

### 网关金额核对（Redsys / Cecabank）

当银行通知平台支付成功时，BuyCourses 会将银行扣款金额（以分为单位，来自已签名的通知）与销售价格进行比较。若二者不一致，则拒绝该通知，销售保持待处理状态，并在 PHP 错误日志中写入一行 `[BuyCourses] Redsys notification refused` 或 `[BuyCourses] Cecabank notification refused`。正常支付不受影响。

若买家已付款但销售仍处于待处理状态，请检查日志：订单创建后价格发生变更，或部分付款，都会在此处显示。核实后，可从销售报告中手动完成此类销售。

### 安全令牌

* 优惠券表单（添加 / 配置）、公开方案卡片表单以及付款操作，均使用与其他插件管理页面相同的 BuyCourses 管理令牌。长时间保持打开的表单，只要会话仍然有效即可继续使用；注销并重新登录后，请先重新加载页面再保存（否则会显示 “Not validated” 消息）。
* “申请发票”页面（`request_invoice.php`）以及 `process_recurring_subscriptions.php` 的 Web 触发器，须在链接中包含令牌（`buycourses_admin_sec_token=...`）。已收藏或通过邮件发送、但未包含该令牌的链接会显示 “Not validated”。命令行/cron 运行方式（`php .../process_recurring_subscriptions.php` 或控制台命令）保持不变，且不需要令牌。
* 成功页面（PayPal、Stripe、订阅、服务）仅向购买该销售的用户显示该笔销售。
* 付款操作（PayPal 批量付款、取消付款）仅限平台管理员（不再接受会话管理员），且必须以 POST 方式并携带令牌提交。

### 日期

订阅销售的结束日期现始终按 UTC 计算，与销售日期相同，与服务器时区无关。

### 多 URL 限制

服务到期时所应用的课程创建与托管限制，遵循与平台其余部分相同的规则：在主 URL 上被锁定或标记为不可更改的设置，不能被其他 URL 覆盖。
