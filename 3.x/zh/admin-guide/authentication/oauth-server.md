# OAuth 2.1 授权服务器与 MCP 客户端

Chamilo 可作为 **OAuth 授权服务器**，供连接其受保护资源的客户端使用。此功能不同于 [OAuth2 登录](oauth2.md)：后者是 Chamilo 借助外部身份提供者完成用户登录。

## 启用与配置

在 **管理 > 配置设置 > 安全** 中启用 `security.oauth_server_enabled`。MCP 访问还取决于现有的 `security.mcp_enabled` 配置以及用户被允许的 MCP 角色。

服务器公开标准的授权、令牌、注册与撤销路由（`/oauth/authorize`、`/oauth/token`、`/oauth/register`、`/oauth/revoke`）以及发现元数据。生产环境中的客户端应仅使用 HTTPS。

## 注册客户端

Chamilo 支持公共 PKCE 授权码客户端以及已注册的机密客户端。动态客户端注册（DCR）使用 `/oauth/register`，并受速率限制。`security.dynamic_client_registration` 设置**默认禁用**；该端点仍可用于受支持的 MCP 注册流程，而该设置控制注册时额外接受的客户端作用域。不要假定切换该设置即可使任意受保护 API 可用。

已注册客户端具有服务器端的**允许资源**列表。目前资源注册表仅定义 **MCP** 资源与 `mcp` 作用域。新增受保护资源需要明确的服务器实现与权限决策，而不仅仅是在请求中添加一个无法识别的 URL。Chamilo 在整个授权与令牌处理过程中校验 RFC 8707 的 `resource` 参数。

## 用户同意与审计

1. 客户端发起带 PKCE（`S256`）以及所请求作用域/资源的授权码请求。
2. 如有必要，用户使用其常规 Chamilo 登录进行身份验证。
3. Chamilo 在同意界面上显示客户端身份、注册详情以及所请求的访问权限。
4. 用户选择 **允许** 或 **拒绝**。批准会被记录为服务器同意历史的一部分，后续请求中可能会显示先前的批准信息。

同意绑定于向用户展示的该次请求。已批准的请求不会授予其他受保护资源，也不会超出所请求权限授予任意访问。

## 部署与安全说明

OAuth 2.1 更新为客户端引入了允许资源字段，以及持久化的客户端同意记录。在启用更新后的流程之前，请应用随版本提供的**特定 Chamilo 数据库迁移**。请妥善保管回调 URL 与 OAuth 客户端密钥。客户端注册并不授予对 Chamilo 用户或课程的不受限制访问。

实现参考：[OAuth 客户端注册与同意，PR #9231](https://github.com/chamilo/chamilo-lms/pull/9231)。
