# 用户连接时长

`GET /api/users/{id}/connection-time` 返回用户连接到平台所花费的总时长。它取代了 1.11.x 版 `webservices/api/v2.php` Web 服务中的 `get_user_total_connexion_time` 操作，并可限定在某一时间段内。

## 访问权限

| 调用方 | 允许范围 |
|--------|---------|
| `ROLE_ADMIN` | 当前访问 URL 下的任意用户 |
| 任何已认证用户 | 仅其本人的连接时长 |
| 其他任何人 | `403 Forbidden` |

该端点使用用户的数字 id。若要从用户名开始，请先通过 `GET /api/users?username=...` 查找该用户。

## 请求

```http
GET /api/users/42/connection-time?startDate=2026-10-01T00:00:00%2B02:00&endDate=2026-12-15T23:59:59%2B01:00
Authorization: Bearer <token>
```

| 查询参数 | 是否必填 | 说明 |
|-----------------|----------|-------------|
| `startDate` | 否 | ISO 8601 日期时间。仅统计在该时刻或之后**开始**的连接。 |
| `endDate` | 否 | ISO 8601 日期时间，不得早于 `startDate`。仅统计在该时刻或之前**结束**的连接。 |

若两个参数均未提供，则统计每一次连接。仅提供 `startDate` 时，从该日期起统计连接，没有结束限制。仅提供 `endDate` 时，统计截至该日期的连接，没有开始限制。

与边界重叠的连接（例如在 `startDate` 之前开始的连接）完全不计入：连接时长从不拆分。这与 1.11.x 报表中自定义时间段筛选器的规则相同。

请包含时区偏移。在 URL 中，`+` 必须编码为 `%2B`。不含偏移的值按服务器时区解读。

## 响应

```json
{
  "id": 42,
  "username": "jdupont",
  "totalConnectionTime": 5025,
  "totalConnectionTimeFormatted": "01:23:45"
}
```

| 字段 | 说明 |
|-------|-------------|
| `totalConnectionTime` | 总时长（秒） |
| `totalConnectionTimeFormatted` | 同一总时长，格式为 `HH:MM:SS`，即 1.11.x Web 服务返回的格式。小时数可以超过 24。 |

## 错误

| 状态 | 何时发生 |
|--------|------|
| `400` | 日期无法解析，或 `endDate` 早于 `startDate` |
| `401` | 无凭据或凭据无效 |
| `403` | 调用方既不是管理员，也不是所查询的用户 |
| `404` | 用户不存在，或不属于当前访问 URL |

## 时长如何计算

总时长是用户在 `track_e_login` 表中各行的 `logout_date − login_date` 之和。

连接从登录时开始，并在用户处于活动状态时延长：用户打开的页面在其标签页可见时每分钟发送一次在线信号，与 Chamilo 1.11.x 中每次页面浏览的行为相同。若非活动时间超过会话生命周期，下一次活动会开启新的连接，因此空闲间隔不计入。注销会关闭当前连接。管理员使用 **Login as** 所花费的时间不会计入该用户。

> **注意：** 在此跟踪功能恢复之前记录的连接可能没有注销日期。它们计为零，因此升级之前时间段的合计可能低于实际花费的时间。
