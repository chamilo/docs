# عناوين URL للوصول

تتيح عناوين URL للوصول لتثبيت واحد من Chamilo خدمة بوابات منفصلة متعددة.

يمكن الوصول إلى هذه الأداة أيضاً من كتلة [المنصة](../platform/README.md) في لوحة تحكم الإدارة، باسم **تكوين عناوين URL متعددة للوصول**.


## حالات الاستخدام

* **عمليات النشر متعددة المستأجرين** — استضافة بوابات تدريب منفصلة لمؤسسات مختلفة على خادم واحد
* **بوابات الأقسام** — منح كل قسم بوابته ذات العلامة التجارية الخاصة (مثل `hr.training.company.com`، `it.training.company.com`)
* **البوابات الإقليمية** — بوابات منفصلة لمناطق أو لغات مختلفة

## آلية العمل

كل عنوان URL للوصول هو نقطة دخول منفصلة إلى تثبيت Chamilo نفسه:

* يمكن تعيين المستخدمين إلى عنوان URL واحد أو أكثر للوصول
* تنتمي المقررات والجلسات إلى عناوين URL محددة للوصول
* يمكن تخصيص إعدادات المنصة لكل عنوان URL للوصول
* يمكن أن تختلف العلامة التجارية والسمات لكل عنوان URL
* لا يمكن لمستخدمي بوابة ما رؤية مستخدمي أو مقررات بوابة أخرى (ما لم تُشارَك صراحة)

## التكوين

### تفعيل عناوين URL المتعددة

يجب تفعيل عناوين URL المتعددة في تكوين Chamilo (عادة في إعدادات البيئة). يُنجَز ذلك عادة أثناء الإعداد الأولي.

### إنشاء عنوان URL للوصول

1. من لوحة الإدارة، انتقل إلى **عناوين URL للوصول**
2. انقر **إضافة URL**
3. أدخل عنوان URL (مثل `https://portal2.yoursite.com`) ووصفاً
4. يمكنك اختيارياً اختيار **عنوان URL الأب** لتضمين هذا العنوان تحت عنوان آخر — انظر [تسلسل عناوين URL](#url-hierarchy) أدناه
5. احفظ

### تعيين المستخدمين والمقررات

* **المستخدمون** — عيّن المستخدمين إلى عناوين URL محددة للوصول. يمكن أن ينتمي المستخدم إلى عناوين URL متعددة.
* **المقررات** — عيّن المقررات إلى عناوين URL محددة للوصول
* **الجلسات** — عيّن الجلسات إلى عناوين URL محددة للوصول

### الإعدادات لكل عنوان URL

يمكن أن يكون لكل عنوان URL للوصول ما يلي:

* **سمة الألوان** — علامة تجارية بصرية مختلفة
* **اسم المنصة والشعار** — هوية مخصصة
* **تجاوزات الإعدادات** — يمكن تخصيص بعض إعدادات المنصة لكل عنوان URL

## تسلسل عناوين URL

يمكن تنظيم عناوين URL للوصول في شجرة أب/ابن بدلاً من قائمة مسطحة. عند إنشاء عنوان URL أو تحريره، يمكن لمسؤول عام غير مقيّد (انظر [مسؤولو الشجرة الفرعية](#subtree-administrators) أدناه) اختيار أي عنوان URL آخر ليكون **عنوان URL الأب**:

![مربع حوار تحرير عنوان URL مع قائمة Parent URL المنسدلة مفتوحة، تعرض عناوين URL الأخرى المتاحة كأب](../../.gitbook/assets/admin-access-url-parent-select.png)

* لا تعرض القائمة المنسدلة أبداً عنوان URL الجاري تحريره، ولا أياً من أحفاده، كأب محتمل — وهذا يمنع إنشاء حلقة. يعيد الخادم التحقق من ذلك بغض النظر عما تعرضه الواجهة.
* إذا أُنشئ عنوان URL دون اختيار أب، فإنه يُعيَّن افتراضياً إلى **عنوان URL لتسجيل الدخول فقط** إن وُجد (انظر [الإعدادات لكل عنوان URL](#per-url-settings) أعلاه)، أو بخلاف ذلك إلى أول عنوان URL للوصول — وهو السلوك الافتراضي نفسه الذي كان قائماً قبل هذه الميزة.
* أعلى عنوان URL في الشجرة — الذي ليس له أب — هو **جذر** تلك الشجرة. يمكن لتثبيت واحد من Chamilo استضافة أكثر من شجرة مستقلة.

أينما تُدرَج عناوين URL للوصول — لوحة عناوين URL المتعددة وصفحة إدارة عناوين URL للوصول — تُعرض الشجرة عبر المسافة البادئة، بحيث يلي الأب مباشرة أبناؤه (يُرتَّب الأشقاء أبجدياً)، بدلاً من عمود منفصل باسم "الأب":

![قائمة عناوين URL للوصول تعرض عنوان URL جذرياً مع عنواني URL فرعيين، أحدهما له عنوان URL فرعي خاص به، بمسافة بادئة تعكس التسلسل](../../.gitbook/assets/admin-access-url-hierarchy-list.png)

## مسؤولو الشجرة الفرعية

يحدد تسلسل عناوين URL أيضاً ما يمكن لـ [المسؤول العام](../users/user-roles.md) إدارته:

* من يُسجَّل على عنوان URL **الجذر** لشجرة يكون **غير مقيّد**: يدير كل عناوين URL للوصول، تماماً كما كان قبل وجود هذه الميزة.
* من يُسجَّل فقط على عنوان URL **غير جذري** يكون **محدود النطاق**: تعرض صفحتا عناوين URL المتعددة وعناوين URL للوصول ذلك العنوان وأحفاده فقط، ويقرأ مخطط تسجيلات الدخول في لوحة عناوين URL المتعددة "تسجيلات الدخول (عناوين URL الخاصة بك)" بدلاً من "تسجيلات الدخول (جميع عناوين URL مجتمعة)".

بغض النظر عن النطاق، تبقى الإجراءات التالية محصورة بمسؤول عام **غير مقيّد** — لا يمكن لمسؤول محدود النطاق تنفيذها حتى لعناوين URL ضمن شجرته الفرعية:

* إنشاء عنوان URL جديد للوصول
* تحرير عنوان URL الخاص بمدخل الوصول أو وصفه أو أبيه
* تفعيل عنوان URL للوصول أو إلغاء تفعيله
* حذف عنوان URL للوصول (لا يمكن حذف عنوان URL الجذر للتثبيت بأكمله، من قِبل أي شخص)
* تسجيل أنفسهم في كل عناوين URL للوصول دفعة واحدة

يمكن لمسؤول محدود النطاق مع ذلك إدارة كل ما هو *معيَّن إلى* عناوين URL في شجرته الفرعية — المستخدمون والمقررات والجلسات والعلامة التجارية والإعدادات — لكن ليس مدخلات عناوين URL للوصول نفسها.

## نصائح

* **قرّر مبكرًا** — إذا اخترت إعداد عناوين URL متعددة، ينبغي القيام بذلك في بداية مشروع Chamilo لأن ذلك يتطلب الإبقاء على عنوان URL الأول خاليًا نسبيًا من المحتوى. تفعيل عناوين URL المتعددة لاحقًا أكثر صعوبة (يتطلب تغييرات يدوية في قواعد البيانات).
* **خطّط لهيكل عناوين URL** — حدّد مخطط عناوين URL قبل إنشاء عناوين URL للوصول، لأن تغيير العناوين لاحقًا يؤثر على جميع الروابط والإشارات المرجعية الموجودة
* **إعداد DNS** — يجب أن يُحلّ كل عنوان URL للوصول إلى خادم Chamilo نفسه. اضبط سجلات DNS وفقًا لذلك.
* **المسؤول العام** — استخدم دور المسؤول العام للإدارة عبر جميع عناوين URL للوصول. لتفويض إدارة فرع واحد فقط، سجّل المسؤول على عنوان URL غير جذري — انظر [مسؤولو الشجرة الفرعية](#subtree-administrators)
