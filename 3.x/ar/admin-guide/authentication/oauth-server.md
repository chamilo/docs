# خادم تفويض OAuth 2.1 وعملاء MCP

يمكن لـ Chamilo أن يعمل بوصفه **خادم تفويض OAuth** للعملاء الذين يتصلون بموارده المحمية. وهذه ميزة مختلفة عن [تسجيل الدخول عبر OAuth2](oauth2.md)، حيث يستخدم Chamilo مزود هوية خارجيًا لتسجيل دخول المستخدمين.

## التمكين والتهيئة

ضمن **الإدارة > إعدادات التهيئة > الأمان**، فعّل `security.oauth_server_enabled`. يعتمد الوصول إلى MCP أيضًا على إعداد `security.mcp_enabled` القائم ودور MCP المسموح به للمستخدم.

يعرض الخادم مسارات التفويض والرمز المميز والتسجيل والإلغاء القياسية (`/oauth/authorize` و`/oauth/token` و`/oauth/register` و`/oauth/revoke`) وبيانات الاكتشاف الوصفية. ينبغي استخدام HTTPS فقط لعملاء بيئة الإنتاج.

## تسجيل عميل

يدعم Chamilo عملاء رمز التفويض العامين الذين يستخدمون PKCE والعملاء السريين المسجّلين. يستخدم التسجيل الديناميكي للعملاء (DCR) المسار `/oauth/register` وهو محدود المعدل. يكون إعداد `security.dynamic_client_registration` **معطّلًا افتراضيًا**؛ وتظل نقطة النهاية متاحة لتدفق تسجيل MCP المدعوم، بينما يتحكم الإعداد في نطاقات العميل الإضافية التي يقبلها التسجيل. لا تفترض أن تبديل الإعداد يجعل واجهات API المحمية التعسفية متاحة.

لدى العملاء المسجّلين قائمة **موارد مسموح بها** على جانب الخادم. يحدد سجل الموارد حاليًا مورد **MCP** ونطاق `mcp` فقط. تتطلب الموارد المحمية الجديدة تنفيذًا صريحًا على الخادم وقرارات بشأن الأذونات، وليس مجرد إضافة عنوان URL غير معروف إلى طلب. يتحقق Chamilo من معلمات `resource` وفق RFC 8707 طوال معالجة التفويض والرمز المميز.

## موافقة المستخدم والتدقيق

1. يبدأ العميل طلب رمز تفويض باستخدام PKCE (`S256`) والنطاق/المورد المطلوب.
2. يصادق المستخدم باستخدام تسجيل الدخول العادي إلى Chamilo إذا لزم الأمر.
3. يعرض Chamilo هوية العميل وتفاصيل التسجيل والوصول المطلوب على شاشة الموافقة.
4. يختار المستخدم **السماح** أو **الرفض**. تُسجَّل الموافقة كجزء من سجل موافقات الخادم، وقد تُعرض معلومات الموافقة السابقة في الطلبات اللاحقة.

تكون الموافقة مرتبطة بالطلب المعروض على المستخدم. لا يمنح الطلب الموافق عليه موارد محمية أخرى أو وصولًا تعسفيًا يتجاوز الأذونات المطلوبة.

## ملاحظات النشر والأمان

تُدخل تحديثات OAuth 2.1 حقل الموارد المسموح بها للعملاء وسجلات دائمة لموافقة العميل. طبّق **ترحيلات قاعدة بيانات Chamilo المحددة** المرفقة مع الإصدار قبل تمكين التدفق المحدَّث. أبقِ عناوين URL لرد الاتصال وأسرار عميل OAuth خاصة. لا يمنح تسجيل العميل وصولًا غير مقيّد إلى مستخدمي Chamilo أو مقرراته.
