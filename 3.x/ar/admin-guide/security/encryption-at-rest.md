# التشفير أثناء التخزين لحقول الملف الشخصي للمستخدم

يمكن لـ Chamilo 3.1 تشفير حقول الملف الشخصي المحددة اختياريًا قبل تخزينها في قاعدة البيانات. تغطي هذه النسخة الأولى من التنفيذ **السيرة الذاتية** و**الهاتف** و**العنوان**. يكون التشفير **معطّلًا افتراضيًا** ويتطلب مفتاح تشفير خاصًا. وهو لا يشفّر جميع معلومات المستخدم، ولا يحل محل أمن القرص أو قاعدة البيانات أو النقل أو النسخ الاحتياطي.

## قبل تمكين التشفير

يجب أن ينفّذ عملية الإطلاق مسؤول المنصة الذي يملك صلاحية الوصول إلى الخادم فقط. أولًا، تأكد من أن التثبيت يتضمن ترحيلات Chamilo 3.1 الخاصة بتخزين الحقول المشفّرة، وخذ نسخة احتياطية قابلة للاستعادة من قاعدة البيانات، وخطّط لنسخة احتياطية آمنة من مفتاح التشفير **بشكل منفصل عن قاعدة البيانات**. اختبر إجراءات الاستعادة قبل تغيير بيانات الإنتاج.

يُخزَّن المفتاح في `var/data-at-rest/master.key`، خارج جذر الويب العام. لا تنشره أبدًا، ولا تلصقه في طلب دعم، ولا تُدرجه في Git. قد يؤدي فقدان المفتاح الأصلي إلى جعل البيانات المشفّرة غير قابلة للقراءة. لا تُنشئ مفتاحًا بديلًا إذا كانت أي بيانات مستخدم مشفّرة بالفعل.

## تهيئة المفتاح

شغّل الأمر مرة واحدة في وضع المعاينة:

```bash
php bin/console chamilo:security:initialize-at-rest-key
```

إذا أفاد بأن لا توجد بيانات مشفّرة وأنه يمكن توفير المفتاح، فقم بتهيئته صراحةً:

```bash
php bin/console chamilo:security:initialize-at-rest-key --apply
```

إذا أفاد الأمر بوجود مفتاح متوافق قائم، فلن يُجرى أي استبدال. إذا كانت هناك صفوف مشفّرة لكن المفتاح مفقود أو غير متطابق، **فتوقف** واستعد المفتاح الأصلي.

## اختيار الحقول المحمية

افتح **الإدارة > الإعدادات > الأمان** وحدّد **السيرة الذاتية** و/أو **الهاتف** و/أو **العنوان** في إعداد حقول المستخدم المشفّرة. حدّد فقط الحقول التي تنوي حمايتها. تستخدم عمليات الكتابة الجديدة إلى الحقول المحددة تشفيرًا موثَّقًا (libsodium XChaCha20-Poly1305)؛ وتبقى سجلات النص الواضح القديمة قابلة للقراءة إلى أن تُملأ رجعيًا بشكل صريح.

## فحص البيانات القائمة وملؤها رجعيًا

لا تعدّل أوامر الملء الرجعي السجلات من دون `--apply`. يُفضَّل مستخدم ضمان جودة واحد قبل دفعة أوسع:

```bash
php bin/console chamilo:security:encrypt-user-biographies --user-id=102
php bin/console chamilo:security:encrypt-user-profile-fields --field=phone --user-id=102
php bin/console chamilo:security:encrypt-user-profile-fields --field=address --user-id=102
```

بعد التحقق من توفر المفتاح واختيار الحقول والنسخ الاحتياطية وحساب ضمان الجودة، شغّل تجربة مقصودة:

```bash
php bin/console chamilo:security:encrypt-user-biographies --user-id=102 --apply
php bin/console chamilo:security:encrypt-user-profile-fields --field=phone --user-id=102 --apply
```

استبدل `102` بمعرّف مستخدم اختبار فعلي. لمجموعات البيانات الأكبر، استخدم الوسيطة الاختيارية `--batch-size` (1–500)، وراجع مخرجات الأمر وسلوك التطبيق، وخطّط للدفعات خلال نافذة صيانة. لا تشغّل ملءًا رجعيًا لقاعدة البيانات بأكملها من دون استراتيجية تراجع مختبَرة.

## القيود التشغيلية

- هذه هي المرحلة الأولى من التشفير على مستوى الحقل، وليست تشفيرًا كاملًا لقاعدة البيانات.
- قد لا تعرف عمليات التكامل والتصدير الأقدم عبر SQL المباشر كيفية قراءة القيم المشفّرة؛ تحقق منها قبل الإطلاق.
- النسخة الاحتياطية من قاعدة البيانات **من دون** مفتاح قابل للاستعادة مقابل لها غير كافية.
- لا تسجّل محتويات الحقول الخام ولا تُدرج مادة المفتاح في التشخيصات.
- التراجع عن رمز التطبيق وحده لا يفك تشفير القيم المخزّنة.
