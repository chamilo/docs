# واجهة برمجة تطبيقات تسجيل الطلاب في الجلسة

يمكن لعمليات التكامل سرد المتعلمين وتسجيلهم وإزالتهم في جلسة باستخدام نقاط نهاية مخصصة للمسؤولين فقط. تستخدم هذه الإجراءات سلوك تسجيل الجلسات في شاشات إدارة Chamilo. وهي منفصلة عن `/api/course-sessions/actions/*`، الذي ينتمي إلى سير عمل مختلف موجّه إلى المدرّسين.

## المصادقة والوصول

تتطلب كل عملية أدناه المصادقة بدور المنصة `ROLE_ADMIN`. كون المستخدم مسؤول جلسة وحده **لا** يمنح الوصول. استخدم أسلوب المصادقة الموضح في [المصادقة](authentication.md).

في التثبيتات متعددة عناوين URL، يجب أن تنتمي الجلسة المطلوبة إلى عنوان URL للوصول الحالي؛ وإلا تستجيب نقطة النهاية بـ `404`.

## المسارات

| الطريقة | نقطة النهاية | الغرض |
|--------|----------|---------|
| `GET` | `/api/sessions/{id}/students` | سرد معرّفات مستخدمي المتعلمين المسجّلين في هذه الجلسة |
| `POST` | `/api/sessions/{id}/students/subscribe` | إضافة المتعلمين المحددين مع الإبقاء على المتعلمين الحاليين |
| `POST` | `/api/sessions/{id}/students/unsubscribe` | إزالة المتعلمين المحددين فقط |

استبدل `{id}` بمعرّف الجلسة الرقمي. لكلا طلبي POST، أرسل JSON يحتوي على مصفوفة `userIds`:

```http
POST /api/sessions/42/students/subscribe
Authorization: Bearer <admin-token>
Content-Type: application/json
```

```json
{ "userIds": [17, 23] }
```

ينتج الاشتراك الناجح استجابة بالبنية التالية؛ وتعتمد المعرّفات على تثبيتك:

```json
{
  "success": true,
  "applied": [17],
  "alreadyThere": [23],
  "ignored": []
}
```

يحتوي `applied` على المتعلمين المسجّلين حديثًا؛ ويحتوي `alreadyThere` على المتعلمين المسجّلين مسبقًا؛ ويسرد `ignored` المعرّفات غير المؤهلة أو غير المتاحة. عند الاشتراك، يسجّل Chamilo أيضًا المتعلمين المضافين في مقررات الجلسة. وهو **لا** يستبدل قائمة الجلسة بالكامل.

لفحص العضوية:

```http
GET /api/sessions/42/students
Authorization: Bearer <admin-token>
```

```json
{ "userIds": [17, 23] }
```

لإزالة متعلمين محددين:

```http
POST /api/sessions/42/students/unsubscribe
Authorization: Bearer <admin-token>
Content-Type: application/json
```

```json
{ "userIds": [17] }
```

تحتوي استجابة إلغاء الاشتراك على `success` و`applied` (المعرّفات المزالة) و`ignored` (المعرّفات غير المسجّلة). يبقى المتعلمون الآخرون في الجلسة.

## التحقق والقيود

* يجب أن تكون `userIds` مصفوفة من المعرّفات الرقمية (أعداد صحيحة أو سلاسل تتكون من أرقام فقط). تُزال تكرارات المعرّفات؛ وتُستبعد القيم غير الموجبة.
* للتسجيل، يجب أن يكون المستخدمون المؤهلون موجودين، وألا يكونوا محذوفين حذفًا ناعمًا، وألا يكونوا مجهولين أو مديري موارد بشرية، وأن ينتموا إلى عنوان URL للوصول الحالي.
* يُرجع JSON أو `userIds` المفقود أو المشوّه `400 Bad Request`.
* تُرجع الجلسات المفقودة أو الخارجة عن النطاق `404 Not Found`؛ ولا يمكن للمستدعين الذين لا يملكون إذن المسؤول استخدام هذه المسارات.
* مسارات تسجيل الطلاب **ليست** نقاط نهاية CRUD عامة لكيان `Session`، ولا تقبل قائمة الجلسة كمستند بديل.

لواجهة الإدارة المقابلة، انظر [إدارة الجلسات](../../admin-guide/sessions/managing-sessions.md). لنسخ جلسة نموذجية قبل تسجيل الطلاب، انظر [تكرار الجلسة](session-duplication.md).
