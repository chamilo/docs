# إنشاء المستخدم

ينشئ `POST /api/access_urls/{id}/user` مستخدمًا على المنصة ويضيفه إلى عنوان الوصول `{id}`. وهو بديل Chamilo 3 لإجراء `save_user_json` في خدمة الويب `webservices/api/v2.php` الخاصة بالإصدار 1.11.x، ومخصّص للتكاملات التي تنشئ حسابات المتعلمين (المتاجر، وأنظمة الموارد البشرية، وبوابات التسجيل).

## الوصول

| المستدعي | مسموح |
|--------|---------|
| `ROLE_ADMIN` | نعم |
| `ROLE_SESSION_MANAGER` | نعم |
| أي شخص آخر | `403 Forbidden` |

قم بالمصادقة باستخدام JWT أو مفتاح API خارجي، كما هو موضّح في [المصادقة](authentication.md).

## الطلب

```http
POST /api/access_urls/1/user
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
  "username": "jdoe-20261022",
  "email": "jane.doe@example.com",
  "firstname": "Jane",
  "lastname": "Doe",
  "password": "S3cret!pass",
  "sendEmail": true,
  "extraFields": { "my_user_field": "value" }
}
```

| الحقل | مطلوب | الوصف |
|-------|----------|-------------|
| `username` | نعم | اسم دخول المستخدم الجديد. يجب ألا يكون مستخدمًا مسبقًا من حساب آخر (تُقارَن القيم دون مراعاة حالة الأحرف). |
| `email` | نعم | عنوان بريد إلكتروني صالح. يمكن لعدة حسابات أن تشترك في العنوان نفسه، ما لم تكن قيمة `checkEmailDuplicates` هي `true`. |
| `firstname`، `lastname` | لا | الاسم الأول واسم العائلة. |
| `password` | لا | كلمة المرور الأولية. عندما تكون فارغة وتكون قيمة `sendEmail` هي `true`، تتضمّن الرسالة رابطًا لتعيين كلمة مرور بدلًا من ذلك. |
| `locale` | لا | لغة الواجهة، مثل `fr_FR`. القيمة الافتراضية هي لغة المنصة. |
| `timezone` | لا | القيمة الافتراضية هي المنطقة الزمنية للمنصة. |
| `status` | لا | `5` (متعلم) افتراضيًا؛ و`1` للمدرّس. |
| `sendEmail` | لا | `true` افتراضيًا. يرسل إلى المستخدم رسالة وبريدًا إلكترونيًا يتضمّنان بيانات الوصول الخاصة به. |
| `checkEmailDuplicates` | لا | `false` افتراضيًا. عندما تكون القيمة `true`، يُرفض الطلب برمز `409 email_already_exists` إذا كان أي حساب يستخدم عنوان البريد الإلكتروني هذا مسبقًا (تُقارَن القيم دون مراعاة حالة الأحرف). السلوك نفسه لمعامل `check_email_duplicates` في `save_user_json`. |
| `extraFields` | لا | قيم الحقول الإضافية للمستخدم، مفتاحها متغير الحقل. يجب أن يكون كل متغير حقلًا إضافيًا موجودًا للمستخدم. |

### عناوين البريد الإلكتروني المشتركة

لا يشترط Chamilo أن تكون عناوين البريد الإلكتروني فريدة: يقبل نموذج إنشاء المستخدم لدى المسؤول عنوانًا يستخدمه حساب آخر مسبقًا، ولا يرفضه استيراد المستخدمين إلا عند تحديد خيار **التحقق من تفرّد البريد الإلكتروني**، ولا يوجد إعداد على المنصة لتغيير ذلك. ومن الحالات الشائعة إعادة تسجيل متعلم بمعرّف جديد مع الإبقاء على العنوان نفسه. أرسل `checkEmailDuplicates: true` فقط عندما تريد تكاملك معاملة العنوان الموجود كخطأ.

عند تفعيل إعداد **تسجيل الدخول هو البريد الإلكتروني**، يكون اسم المستخدم هو عنوان البريد الإلكتروني، لذا يرفض فحص اسم المستخدم التكرارات مسبقًا.

## الاستجابة

`201 Created` مع المستخدم الجديد (مجموعة التسلسل `user:read`)، بما في ذلك `id` الخاص به.

## الأخطاء

| الحالة | المتن | متى |
|--------|------|------|
| `401` | | لا توجد بيانات اعتماد أو أنها غير صالحة |
| `403` | | المستدعي ليس مسؤولًا ولا مسؤول جلسة |
| `409` | `{"error": "username_already_exists"}` | اسم المستخدم مستخدم مسبقًا |
| `409` | `{"error": "email_already_exists"}` | قيمة `checkEmailDuplicates` هي `true` وعنوان البريد الإلكتروني مستخدم مسبقًا |
| `422` | | `username` أو `email` مفقود، أو عنوان البريد الإلكتروني غير صالح |

## التنفيذ

* العملية: مورد `AccessUrlUser` المُعلَن في `src/CoreBundle/Entity/User.php`
* الإدخال: `src/CoreBundle/Dto/CreateUserOnAccessUrlInput.php`
* المتحكّم: `src/CoreBundle/Controller/Api/CreateUserOnAccessUrlAction.php`
* تستخدم صفحة **تسجيل الطالب** لدى مسؤول الجلسة (`/admin-dashboard/register/{courseId}`) نقطة النهاية هذه مع `checkEmailDuplicates: true`، لذا تحذّر عندما يكون العنوان مستخدمًا مسبقًا.
