# تكرار الجلسة

ينشئ `POST /api/sessions/{id}/duplicate` جلسة جديدة من **جلسة نموذج** موجودة. وهو بديل Chamilo 3 لإجراء `create_session_from_model` في خدمة الويب `webservices/api/v2.php` للإصدار 1.11.x، ومخصّص للتكاملات التي تفتح دورة تدريب جديدة انطلاقًا من جلسة قالب.

## الوصول

| المستدعي | المسموح |
|--------|---------|
| `ROLE_ADMIN` | أي جلسة |
| `ROLE_SESSION_MANAGER` | الجلسات التي يديرونها فقط (يكونون مسؤولي جلسة للنموذج)، ما لم يكن إعداد **السماح لمسؤولي الجلسات برؤية جميع الجلسات** مفعّلًا |
| أي شخص آخر | `403 Forbidden` |

قم بالمصادقة باستخدام JWT أو مفتاح API خارجي، كما هو موضّح في [المصادقة](authentication.md).

## الطلب

```http
POST /api/sessions/42/duplicate
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
  "title": "Accounting basics - October 2026",
  "startDate": "2026-10-01T09:00:00+02:00",
  "endDate": "2026-12-15T18:00:00+01:00",
  "extraFields": { "my_session_field": "value" },
  "copySessionContent": false
}
```

| الحقل | مطلوب | الوصف |
|-------|----------|-------------|
| `title` | نعم | عنوان الجلسة الجديدة. يجب ألا يكون مستخدمًا مسبقًا من جلسة أخرى (150 حرفًا كحد أقصى). |
| `startDate` | نعم | تاريخ ووقت بصيغة ISO 8601. يُستخدم كتاريخ بدء الوصول والعرض ووصول المدرب. |
| `endDate` | نعم | تاريخ ووقت بصيغة ISO 8601، لا يسبق `startDate`. يُستخدم كتاريخ انتهاء الوصول والعرض ووصول المدرب. |
| `extraFields` | لا | قيم الحقول الإضافية للجلسة مفهرسة بمتغير الحقل. وهي تتجاوز القيم المنسوخة من النموذج. يجب أن يكون كل متغير حقلًا إضافيًا موجودًا للجلسة. |
| `copySessionContent` | لا | `false` افتراضيًا. عند تعيينه إلى `true`، يُكرَّر المحتوى الخاص بالجلسة لكل مقرر (المستندات، ومسارات التعلم، والاختبارات، وأحداث التقويم، والإعلانات، ودفتر الدرجات…) في الجلسة الجديدة. يُشارَك محتوى المقرر الأساسي دائمًا ولا يُنسخ أبدًا. هذا الخيار مستقل عن إعداد المنصة **تفعيل نسخ المحتوى الخاص بالجلسة إلى جلسة أخرى**. |

## ما الذي يُنسخ

| يُنسخ من النموذج | لا يُنسخ |
|-----------------------|------------|
| التصنيف، والظهور، والمدة، والوصف، و«إظهار الوصف» | مدربو المقررات |
| قيم الحقول الإضافية للجلسة | مديرو الموارد البشرية (DRH) |
| المقررات، بالترتيب نفسه | الطلاب |
| المدربون العامون | |
| مسؤولو الجلسة (إذا لم يكن للنموذج أي منهم، يصبح المستدعي مسؤول الجلسة) | |
| خيار «إرسال إشعار الاشتراك» | |
| العرض الترويجي | |
| محتوى المقرر الخاص بالجلسة، فقط عندما تكون قيمة `copySessionContent` هي `true` | |

يُستبعد الطلاب عمدًا: تحصل كل دورة على متعلميها الخاصين. اشتركهم لاحقًا باستخدام `POST /api/course-sessions/actions/subscribe-users`.

تُربط الجلسة الجديدة بعنوان URL للوصول الحالي.

## الاستجابة

`201 Created` مع الجلسة الجديدة:

```json
{
  "id": 57,
  "title": "Accounting basics - October 2026",
  "nbrCourses": 3,
  "visibility": 1,
  "generalCoachesSubscriptions": [{ "user": "/api/users/7" }]
}
```

## الأخطاء

| الحالة | متى |
|--------|------|
| `401` | لا توجد بيانات اعتماد أو أنها غير صالحة |
| `403` | لا يجوز للمستدعي إدارة جلسة النموذج |
| `404` | جلسة النموذج غير موجودة |
| `422` | حقل مفقود أو غير صالح، أو `endDate` يسبق `startDate`، أو العنوان مستخدم مسبقًا، أو متغير حقل إضافي غير معروف |

تُنفَّذ جميع عمليات التحقق قبل إنشاء أي شيء، لذا لا يترك الطلب المرفوض جلسة جزئية خلفه.

## التنفيذ

* العملية: `duplicate_session` على مورد `Session` (`src/CoreBundle/Entity/Session.php`)
* الإدخال: `src/CoreBundle/Dto/SessionDuplicateInput.php`
* المعالج: `src/CoreBundle/State/Session/SessionDuplicateProcessor.php`، الذي يستدعي `SessionManager::copy()` (المستخدم أيضًا في إجراء **نسخ** ضمن قائمة الجلسات) ثم يطبّق العنوان والتواريخ والحقول الإضافية المطلوبة، بالإضافة إلى العرض الترويجي للنموذج ومسؤولي الجلسة وخيار الإشعار وترتيب المقررات.
