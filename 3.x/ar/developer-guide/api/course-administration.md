# واجهة برمجة تطبيقات إدارة المقررات

يتيح Chamilo 3.1 لتكاملات المسؤولين تحديث بيانات المقررات الوصفية وحذف المقررات عبر مورد واجهة `Course`. أُضيفت هذه العمليات للمزامنة مع أنظمة الإدارة الخارجية، مثل نظام تخطيط موارد المؤسسة (ERP).

## الصلاحيات

| العملية | الأسلوب ونقطة النهاية | الدور المطلوب |
|-----------|---------------------|---------------|
| سرد المقررات | `GET /api/courses` | معلّم أو مسؤول المنصة |
| عرض مقرر | `GET /api/courses/{id}` | صلاحية عرض ذلك المقرر |
| إنشاء مقرر | `POST /api/courses` | معلّم أو مسؤول المنصة |
| تحديث مقرر | `PATCH /api/courses/{id}` | **مسؤول المنصة (`ROLE_ADMIN`)** |
| حذف مقرر | `DELETE /api/courses/{id}` | **مسؤول المنصة (`ROLE_ADMIN`)** |

لم يُضبط `PUT` كعملية على هذا المورد. ينبغي أن يواصل المعلّمون تحرير مقرراتهم الخاصة عبر واجهة إعدادات المقرر؛ عمليات الكتابة الجديدة في واجهة البرمجة مقصورة على المسؤولين.

استخدم حسابًا مصادقًا عليه أو بيانات اعتماد تكامل بالصلاحيات اللازمة. راجع [مصادقة واجهة البرمجة](authentication.md).

## تحديث بيانات المقرر الوصفية

أرسل طلب JSON Merge Patch عبر API Platform لتغيير الخصائص المُرسلة في المتن فقط:

```http
PATCH /api/courses/42
Authorization: Bearer <admin-token>
Content-Type: application/merge-patch+json
Accept: application/ld+json
```

```json
{
  "title": "Introduction to Accounting - 2026"
}
```

يحدّث الطلب المقرر القائم بدلًا من إنشاء مقرر جديد. تقبل واجهة البرمجة الخصائص القابلة للكتابة المعرّفة بمجموعة المُسلسِل `course:write`، مع مراعاة التحقق من صحة الكيان. تشمل الأمثلة `title` و`visibility` و`categories` و`departmentUrl` و`videoUrl` و`sticky` و`duration`. تتطلب خصائص العلاقات مثل `categories` تمثيل المورد الذي تتوقعه واجهة البرمجة؛ راجع توثيق OpenAPI بدلًا من إرسال معرّفات قاعدة بيانات عشوائية.

**مهم:** الرمز الداخلي للمقرر `code` **غير** قابل للكتابة عبر عملية PATCH هذه. لا تحاول إعادة تسمية الرمز الداخلي لمقرر بإرسال الحقل `code` أو `visualCode`.

## حذف مقرر

```http
DELETE /api/courses/42
Authorization: Bearer <admin-token>
```

هذه عملية إدارية **تدميرية**. يستدعي Chamilo مساعد حذف المقرر نفسه المستخدم في صيانة المقررات بدلًا من حذف كيان Doctrine مباشرة. ينظّف التسجيلات المرتبطة وروابط الجلسات والفصول وبيانات التتبع وفهرسة البحث ذات الصلة حسب الاقتضاء.

في تثبيت **متعدد عناوين URL**، قد يقتصر الحذف على فصل المقرر عن عنوان الوصول الحالي بدلًا من حذفه في كل مكان. لا تُحذف وثائق المقرر باستخدام خيار *حذف الوثائق الحصرية* المنفصل من واجهة الصيانة. لا تفسّر حذفًا عبر واجهة البرمجة على أنه ضمان بإزالة كل وثيقة فعليًا.

إذا منع اعتماد نشط الحذف (على سبيل المثال، تسلسل موارد)، يمكن لنقطة النهاية أن تستجيب بـ `409 Conflict`. راجع اعتمادات المقرر والنسخ الاحتياطية قبل إرسال طلبات DELETE، خصوصًا في التكاملات الدفعية.

## الأخطاء وملاحظات تشغيلية

* يُرفض المستدعي الذي لا يملك دور المسؤول المطلوب؛ استخدم حسابًا مخوّلًا بشكل صحيح بدلًا من بيانات اعتماد معلّم لعمليات PATCH أو DELETE.
* قد تفشل بيانات الطلب غير الصالحة في التحقق من صحة الكيان. اجلب المقرر الحالي قبل تصحيحه، وأرسل فقط الخصائص التي تنوي تغييرها.
* تُعرض هذه العمليات بواسطة API Platform؛ راجع توثيق OpenAPI للنسخة المثبتة لمعرفة مخطط الاستجابة الدقيق وتنسيقات الحقول المقبولة.
* اختبر حذف المقرر على مقرر يمكن الاستغناء عنه، لا على مقرر يحتوي سجلات متعلمين إنتاجية.

لإدارة المقررات في الواجهة، راجع [إدارة المقررات](../../admin-guide/courses/managing-courses.md). لتكاملات تسجيل الجلسات، راجع [تسجيل الطلاب في الجلسة](session-students.md).
