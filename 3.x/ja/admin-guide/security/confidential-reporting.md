# 機密通報

Chamilo には、他のユーザーに関する懸念を権限のある調査担当者へ提出するための、任意の**機密通報**ワークフローが含まれています。これは通常のサポートチケットツールでも、公開のディスカッションフォーラムでもありません。

## 機能を有効にする

**Administration > Configuration settings > Security** を開き、次を設定します。

| Setting | Default | Purpose |
|---|---|---|
| `security.confidential_reporting_enabled` | `false` | 機密通報ワークフローを有効にする |
| `security.confidential_reporting_min_reporters` | `2` | 調査が閲覧可能になるまでに必要な、異なる通報者の最小人数（2～10） |
| `security.confidential_reporting_attachments_enabled` | `true` | 証拠の添付を許可する |
| `security.confidential_reporting_notifications_enabled` | `false` | 対象となる調査について内部インジケーターを表示する（メールは送信しない） |

導入環境では、サーバー側の機密通報用暗号化とプライベートストレージが利用可能な状態であることも必要です。Chamilo は PHP Sodium の暗号関数とプライベートな暗号化キーを使用します。**そのキーは安全に保管し、バックアップしてください**。キーを失うと、保存済みの通報が読めなくなる可能性があります。キーを Git リポジトリにコピーしないでください。プライベートキーの保管と必要なデータベースマイグレーションが動作することを確認する前に、この機能を有効にしないでください。

## 通報を提出する

1. Chamilo に直接サインインし、**Confidential reporting** を開きます（ポータルで有効になっている場合）。
2. 対象となる人物を選び、件名を入力し、事案を記述します。
3. 添付が有効な場合は、証拠を追加します。
4. この特定の通報について、調査担当者があなたの**氏名とメールアドレス**を閲覧してよいかを決定します。この許可は後から撤回できます。
5. 通報を送信します。**My confidential reports** を使って案件を追跡し、調査担当者とメッセージをやり取りします。

通報者の身元は、**既定では調査担当者に表示されません**。これは機密性を保つための制御であり、システムの運用者に対する絶対的な匿名性を約束するものではありません。

## 調査の権限としきい値

調査には専用の `welfare:investigate` 権限と、対象となる管理者または HR ロールが必要です。案件は、同一の対象について設定された人数の**異なる通報者**に達した後にのみ、調査可能になります。調査担当者は、自分自身に関する通報を調査できません。HR のアクセスは、HR マネージャーがフォローしているユーザーに限定されます。

調査担当者は **Confidential investigations** にアクセスし、対象となる案件の閲覧、証拠の確認、メッセージのやり取りを行います。しきい値未満の案件、または権限のない案件は、調査 API を通じて公開されません。管理上の**なりすまし**では、機密通報へのアクセスは提供されません。

## プライバシーと運用上の注意

通報および添付された証拠には、機微な個人データが含まれます。調査担当者の権限を制限し、バックアップへのアクセスを限定し、組織として適切な保存期間ポリシーを定め、通報者、対象者、調査担当者を別々のアカウントでワークフローをテストしてください。通報の全文を技術ログや課題管理ツールにコピーすることは避けてください。
