# ユーザープロフィール項目の保存時暗号化

Chamilo 3.1 では、選択した個人プロフィール項目をデータベースに保存する前に、任意で暗号化できます。この最初の実装では、**経歴**、**電話番号**、**住所**を対象とします。暗号化は**既定では無効**であり、秘密の暗号化鍵が必要です。すべてのユーザー情報を暗号化するわけではなく、ディスク、データベース、通信、バックアップのセキュリティを置き換えるものでもありません。

## 暗号化を有効にする前に

展開作業は、サーバーへのアクセス権を持つプラットフォーム管理者のみが実施してください。まず、インストールに暗号化項目の保存用 Chamilo 3.1 マイグレーションが含まれていることを確認し、復元可能なデータベースバックアップを取得し、暗号化鍵の安全なバックアップを**データベースとは別に**計画してください。本番データを変更する前に、復元手順をテストしてください。

鍵は公開ウェブのドキュメントルート外の `var/data-at-rest/master.key` に保存されます。公開したり、サポート依頼に貼り付けたり、Git にコミットしたりしないでください。元の鍵を失うと、暗号化されたデータを読み取れなくなる可能性があります。ユーザーデータがすでに暗号化されている場合は、代替鍵を生成しないでください。

## 鍵の初期化

プレビューモードでコマンドを一度実行します。

```bash
php bin/console chamilo:security:initialize-at-rest-key
```

暗号化されたデータが存在せず、鍵をプロビジョニングできると報告された場合は、明示的に初期化します。

```bash
php bin/console chamilo:security:initialize-at-rest-key --apply
```

既存の互換性のある鍵があると報告された場合、置き換えは行われません。暗号化済みの行が存在するのに鍵がない、または一致しない場合は、**作業を中止**し、元の鍵を復旧してください。

## 保護する項目の選択

**管理 > 設定 > セキュリティ**を開き、暗号化ユーザー項目の設定で**経歴**、**電話番号**、および／または**住所**を選択します。保護する意図のある項目のみを選択してください。選択した項目への新しい書き込みには、認証付き暗号化（libsodium XChaCha20-Poly1305）が使用されます。従来の平文レコードは、明示的にバックフィルされるまで読み取り可能なままです。

## 既存データの確認とバックフィル

バックフィルコマンドは、`--apply` なしではレコードを変更しません。より広いバッチの前に、単一の QA ユーザーで確認することを推奨します。

```bash
php bin/console chamilo:security:encrypt-user-biographies --user-id=102
php bin/console chamilo:security:encrypt-user-profile-fields --field=phone --user-id=102
php bin/console chamilo:security:encrypt-user-profile-fields --field=address --user-id=102
```

鍵の利用可能性、項目の選択、バックアップ、および QA アカウントを確認したうえで、意図的なパイロットを実行します。

```bash
php bin/console chamilo:security:encrypt-user-biographies --user-id=102 --apply
php bin/console chamilo:security:encrypt-user-profile-fields --field=phone --user-id=102 --apply
```

`102` は実際のテストユーザー ID に置き換えてください。より大きなデータセットでは、任意の `--batch-size` 引数（1–500）を使用し、コマンド出力とアプリケーションの動作を確認し、メンテナンス時間帯にバッチを計画してください。検証済みのロールバック戦略なしに、データベース全体のバックフィルを実行しないでください。

## 運用上の制限

- これは項目レベルの暗号化の第1段階であり、データベース全体の暗号化ではありません。
- 古い直接 SQL 連携やエクスポートは、暗号化された値の読み取り方法を認識していない場合があります。展開前に確認してください。
- 対応する復元可能な鍵**がない**データベースバックアップでは不十分です。
- 生の項目内容をログに記録したり、診断情報に鍵素材を含めたりしないでください。
- アプリケーションコードだけをロールバックしても、保存済みの値は復号されません。

一般的なプラットフォームのセキュリティオプションについては、[セキュリティ設定](../platform-settings/security-settings.md)を参照してください。実装: [Chamilo LMS PR #9491](https://github.com/chamilo/chamilo-lms/pull/9491)。
