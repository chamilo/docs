# 達成証明書（バッチ生成）

Chamilo は、コースを修了したすべての受講者に対して、そのコースの達成証明書を自動生成できます。対象はベースコース内、およびそのコースを再利用するすべてのセッション内であり、教員が各コースを個別に開く必要はありません。これを担うコンソールコマンドは2つあり、1つは単一コース用、もう1つはプラットフォーム全体用です。いずれも、常時監視が必要なデータベース負荷の高い処理ではありません。どちらも上限付きのバッチで動作し、ドライランに対応し、中断されても安全に再開できます。

## プラットフォーム全体向けコマンド

```bash
php bin/console chamilo:gradebook:process-achievement-certificates [options]
```

適格なルート成績表カテゴリ（最上位であり、サブカテゴリではなく、**証明書を生成**が有効）を持つすべてのコースについて、このコマンドは、そのカテゴリの証明書をまだ持たない登録済み受講者をすべて評価し、修了要件を満たした受講者に証明書を生成します。1つのコースは**複数の**コンテキストを持ち得ます。ベースの登録、およびそのコースを再利用するセッションごとに1つのコンテキストです。セッションは独自のルートカテゴリと独自の合格しきい値を持てるためです。

コース、またはそのセッションコンテキストのいずれかは、自動処理の対象外である場合、エラーとして扱われずスキップされます。対象外となるのは、修了ルールが設定されていない場合、そのコンテキストに適格なルートカテゴリが複数ある場合（曖昧であり、手動での選択が必要）、または証明書通知の内容が欠落している場合です。実行終了時のサマリーには、各ケースに該当したコンテキスト数が報告されるため、スキップされたものが表面化せずに終わることはありません。

### 修了判定のソース

* `--completion-mode=course-rule`（既定）: コースに設定された修了ルールを使用します。
* `--completion-mode=gradebook`: 代わりに、そのコンテキストのネイティブな成績表スコアを直接使用します。
  このモードで対象となるのは、適格なルートカテゴリがちょうど1つあるコンテキストのみです。複数あるコンテキストはスキップされて報告され、個別に処理します（下記を参照）。

### 安全のためのオプション

| Option                     | Purpose                                                                                                                                 |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `--dry-run`                 | 証明書を作成せず、通知も送信せずに評価と報告のみを行います。必ず最初にこれを実行してください。                                      |
| `--send-notification`       | 実際の（ドライランではない）実行に必須です。証明書が作成されるたびに、コースに設定された内部メッセージと電子メールを送信します。 |
| `--sender-id=<id>`          | 通知の送信者として使用する、有効なプラットフォーム管理者。`--send-notification` と併せて必須です。                            |
| `--limit=<n>`                | 1回の実行で生成する（ドライランでは報告する）証明書の最大数。`0` = 無制限。既定値は `100`。                                    |
| `--scan-limit=<n>`           | 1回の実行で、すべてのコースとセッションにわたって評価する受講者の最大数。`0` = 無制限。既定値は `1000`。                                 |
| `--batch-size=<n>`           | 1つのコース／セッションコンテキスト内で、データベースの1バッチあたりに読み込む受講者数。既定値は `25`。                                                     |
| `--course-batch-size=<n>`    | データベースの1バッチあたりに読み込むコース数。既定値は `50`。                                                                                         |
| `--after-course-id=<id>`     | このコース ID の後からスキャンを再開します。中断された実行の後に再利用しても安全です。コースは、すでに証明書を持つ受講者に対して証明書を再生成することはありません。 |
| `--user-id=<id>`             | 実行を1人の受講者に限定し、適格なすべてのコースとセッションにわたって確認します。プラットフォーム全体の実行前に動作を検証するのに有用です。 |
| `--regenerate-empty`         | 証明書レコードは存在するが、保存された証明書ファイルがない受講者も処理します。たとえば生成が途中で失敗した後などです。その証明書を再度生成します。完全な証明書を持つ受講者は一切変更されません。 |

### 例

まずプラットフォーム全体をドライランし、何が生成されるかを確認します。

```bash
php bin/console chamilo:gradebook:process-achievement-certificates --dry-run
```

実際に実行し、学習者へ通知します。送信者は ID 1 の管理者です。

```bash
php bin/console chamilo:gradebook:process-achievement-certificates \
  --send-notification --sender-id=1
```

コース 480 の後から、中断した実行を再開します。

```bash
php bin/console chamilo:gradebook:process-achievement-certificates \
  --send-notification --sender-id=1 --after-course-id=480
```

記録は存在するがファイルが一度も保存されていない証明書を再生成します（まずドライランで一覧表示します）。

```bash
php bin/console chamilo:gradebook:process-achievement-certificates \
  --regenerate-empty --dry-run
php bin/console chamilo:gradebook:process-achievement-certificates \
  --regenerate-empty --send-notification --sender-id=1
```

### cron ジョブとしてのスケジュール

```cron
# Every night at 2 AM
0 2 * * * php /path/to/chamilo/bin/console chamilo:gradebook:process-achievement-certificates --send-notification --sender-id=1 -e prod --no-interaction >> /path/to/chamilo/var/log/achievement-certificates.log 2>&1
```

## 1 つのコースを個別に処理する

`chamilo:migration:process-achievement-certificates --course-id=<id>` は、プラットフォーム全体向けコマンドと同じドライラン、通知、ページネーションのオプションを提供します。対象はベースコースのみ（そのセッションは含みません）で、コースに複数の対象ルートカテゴリがある場合に曖昧さを解消するため、明示的な `--category-id` を指定します。

```bash
php bin/console chamilo:migration:process-achievement-certificates \
  --course-id=42 --category-id=7 --dry-run
```

プラットフォーム全体の実行の前に単一のコースをテストする場合、またはプラットフォーム全体の実行でカテゴリが曖昧なためスキップされたと報告されたコースを処理する場合に使用します。

## 終了コード

いずれのコマンドも、実際の実行中に少なくとも 1 件の証明書生成が失敗した場合は失敗ステータスで終了します（根本原因のエラーは `var/log/dev.log`、または本番環境の同等のログを確認してください）。構造上の理由でスキップされたコンテキスト（ルールがない、カテゴリが曖昧、通知設定がない）は失敗の終了コードにはなりません。代わりにサマリーに報告されます。

## 関連: 前提条件のラーニングパスで 100% 未満のまま止まっている学習者

コースの完了ルールがラーニングパスの 100% 到達を要求している場合、すべてのステップを終えていてもパスの最後の「Congratulations」ページを一度も開いていない学習者は、100% の直前で止まり、ここでは対象になりません。
[完了しないラーニングパスの最終項目を完了させる](learning-path-final-items.md) を参照してください。学習者が取得しているはずの証明書が欠けている場合は、先にこれを実行してください。

## 廃止: 従来の cron スクリプト

`public/main/cron/add_gradebook_certificates.php` は推奨されなくなりました。プラットフォーム上のすべての成績表結果を、上限のない単一のクエリでメモリに読み込み、ループ中に解放しないため、コースや演習が少なくないインスタンスではメモリを使い果たす可能性があります。また、「証明書を取得しました」という通知も送信しません。代わりに `chamilo:gradebook:process-achievement-certificates` を使用してください。
