# FAQ

Chamilo 3.0 管理者向けのよくある質問です。

## Installation and Setup

**Q: Chamilo 3.0 が必要とする PHP のバージョンは何ですか？**
A: PHP 8.3、8.4、または 8.5 です。[サーバー要件](../installation/server-requirements.md) を参照してください。

**Q: 共有ホスティングで Chamilo を実行できますか？**
A: 可能ですが、推奨されません。Chamilo 3.0 は Composer、開発モードでの Node.js、およびインストールとメンテナンスのためのコマンド
ラインアクセスを必要とします。VPS または専用サーバーの方がはるかに良い体験を提供します。

**Q: どのデータベースを使うべきですか？**
A: MySQL 8.0+ または MariaDB 10.4+ が最も一般的に使われ、最もよくテストされています。

**Q: コマンドラインなしで Chamilo をインストールできますか？**
A: はい、パッケージ版（.zip または .tar.gz）を使う場合です。それ以外では、Composer の依存関係のインストール、フロントエンドアセットのビルド、データベースマイグレーションの実行にコマンドラインが必要です。Web ベースのウィザードはデータベース設定と初期構成を扱いますが、周辺の手順は開発モードではシェルアクセスが必要です。

## Users and Authentication

**Q: ユーザーのパスワードをリセットするにはどうすればよいですか？**
A: **管理 > ユーザー一覧** に移動し、ユーザーを見つけて編集をクリックし、新しいパスワードを設定します。あるいは、ユーザーはログインページの「パスワードを忘れた」リンクを使えます（メールが設定されている場合）。

**Q: ユーザーを一括インポートできますか？**
A: はい。**管理 > ユーザーのインポート** に移動し、ユーザーデータを含む CSV または XML ファイルをアップロードします。インポートは新規ユーザーの作成と既存ユーザーの更新に対応しています。

**Q: LDAP または Active Directory と統合するにはどうすればよいですか？**
A: 認証設定で LDAP 設定を構成します。[LDAP](../authentication/ldap.md) を参照してください。ユーザーはログイン時、またはスケジュールされた同期で同期されます。

**Q: ユーザーは同時に複数のセッションに所属できますか？**
A: はい。ユーザーは任意の数のセッションに同時に登録できます。各セッションは進捗を独立して追跡します。

## Courses and Content

**Q: 単一のコースをバックアップするにはどうすればよいですか？**
A: コース内で **メンテナンス > バックアップの作成** に移動します。これにより、コースのコンテンツと設定のダウンロード可能なアーカイブが生成されます。同じまたは別の Chamilo インスタンスに復元できます。

**Q: コースをコピーできますか？**
A: はい。**管理 > コースのコピー** またはコース内のコースメンテナンスツールを使います。コース間でコンテンツをコピーしたり、既存のコースから新しいコースを作成したりできます。

**Q: どの SCORM バージョンがサポートされていますか？**
A: Chamilo は SCORM 1.2 をサポートします。SCORM パッケージはラーニングパスとしてインポートされます。

**Q: コースを作成できる人を制限するにはどうすればよいですか？**
A: **管理 > 設定 > コース** に移動し、**管理者以外（教師）が新しいコースを作成することを許可する**（`allow_users_to_create_courses`）を無効にします。無効にすると、管理者のみがコースを作成できます。あるいは、教師が作成できるコース数に上限を設定することもできます。

## Performance and Maintenance

**Q: プラットフォームが遅いです。最初に何を確認すべきですか？**
A: 影響の大きい順に、(1) `.env` で `APP_ENV=prod` および `APP_DEBUG=0` であることを確認する。(2) PHP OPcache が有効であることを確認する。(3) データベースのパフォーマンスを確認する。(4) [パフォーマンスチューニング](../platform-settings/performance-tuning.md) を参照する。

**Q: キャッシュをクリアするにはどうすればよいですか？**
A: コマンドラインから `php bin/console cache:clear --env=prod` を実行します。アプリケーションの実行中に `var/cache/` ディレクトリを手動で削除しないでください。

**Q: Chamilo にはどれくらいのディスク容量が必要ですか？**
A: アプリケーション自体は非圧縮で約 2 GB 必要です。合計容量はアップロードされたコンテンツ（ドキュメント、動画、SCORM パッケージ）に依存します。ディスク使用量を監視し、それに応じて計画してください。

**Q: 自動バックアップを設定するにはどうすればよいですか？**
A: [バックアップ](../maintenance/backups.md) を参照してください。最低限、毎日のデータベースダンプと、アップロードディレクトリの定期的なファイルレベルのバックアップをスケジュールしてください。

## Email

**Q: ユーザーがメールを受信していません。何を確認すべきですか？**
A: (1) `.env` の `MAILER_DSN` を確認する。(2) `php bin/console mailer:test someone@example.com` を実行してテストする。(3) 迷惑メールフォルダを確認する。(4) SPF/DKIM の DNS レコードを確認する。[メール設定](../installation/email-configuration.md) を参照してください。

**Q: メール送信に Gmail を使えますか？**
A: はい、小規模なプラットフォームや開発用途では可能です。アプリパスワードを使い、Gmail の 1 日あたりの送信上限（通常アカウントでは 500 通/日）に注意してください。

## Security

**Q: HTTPS を強制するにはどうすればよいですか？**
A: Web サーバーを HTTP から HTTPS へリダイレクトするよう設定します。さらに、**管理 > 設定 > セキュリティ** で「HTTPS を強制」設定を有効にします。[セキュリティ設定](../platform-settings/security-settings.md) を参照してください。

**Q: ブルートフォースのログイン攻撃をブロックするにはどうすればよいですか？**
A: セキュリティ設定で最大ログイン試行回数と CAPTCHA を構成します。追加の保護として、サーバーレベルで fail2ban を使うことも検討してください。

**Q: ユーザーがパスワードを忘れ、メールが動作していません。どう助けますか？**
A: 管理者として、ユーザーアカウントを直接編集し、新しいパスワードを設定します。**管理 > ユーザー一覧** に移動し、アカウントを見つけてパスワード欄を更新します。

## アップグレード

**Q: Chamilo 2.x から 3.0 へ直接アップグレードできますか？**
A: はい。ただし、単純な更新ではなく大規模な移行です。[アップグレード](../installation/upgrading.md) を参照してください。必ずステージングサーバーで先にテストしてください。

**Q: 3.0 へアップグレードした後もプラグインは動作しますか？**
A: いいえ。2.x のプラグインは 3.0 と互換性がなく、書き直すか、同等の 3.0 の機能に置き換える必要があります。
