## セッションを理解する

セッションは**任意**です。コースだけでもポータルは運用できますが、長期的な管理作業を減らす手段として、セッションという追加の複雑さを検討することを**強く**推奨します。

**コース**はコンテンツ（ドキュメント、演習、学習パス）を保持します。**セッション**は、そのコース（または複数のコース）を、特定の学習者グループに*特定の期間*割り当てます。

このアーキテクチャの意味は次のとおりです。

* 教師はコース内でコンテンツを一度だけ作成する
* 管理者はセッションを作成し、そのコンテンツを異なるコホートに提供する
* 各セッションには独自の登録、追跡データ、結果がある
* ベースとなるコースコンテンツは共有されるが、セッションチューターは一部の要素をカスタマイズできる

## セッションを使うべきとき

次のような場合にセッションを使用します。

* 同じ研修を複数回実施する（例：毎月のオンボーディングセッション）
* コホート型のプログラムがある（例：学期単位のクラス）
* 学習者グループごとに個別の追跡が必要である
* 同じコースの異なる実施回を、異なるチューターに管理させたい
