# アクセス URL

アクセス URL を使うと、1 つの Chamilo インストールで複数の独立したポータルを提供できます。

このツールは、管理ダッシュボードの [プラットフォーム](../platform/README.md) ブロックから **複数アクセス URL の設定** としても利用できます。


## 利用ケース

* **マルチテナント展開** — 1 台のサーバー上で、異なる組織向けの独立した研修ポータルをホストする
* **部門ポータル** — 各部門に独自のブランディングを施したポータルを提供する（例: `hr.training.company.com`、`it.training.company.com`）
* **地域ポータル** — 地域や言語ごとにポータルを分ける

## 仕組み

各アクセス URL は、同一の Chamilo インストールに対する独立した入口です。

* ユーザーは 1 つ以上のアクセス URL に割り当てられます
* コースとセッションは特定のアクセス URL に属します
* プラットフォーム設定はアクセス URL ごとにカスタマイズできます
* ブランディングとテーマは URL ごとに変えられます
* あるポータルのユーザーは、明示的に共有されない限り、別のポータルのユーザーやコースを見ることはできません

## 設定

### マルチ URL の有効化

マルチ URL は Chamilo の設定（通常は環境設定）で有効にする必要があります。これは通常、初期セットアップ時に行います。

### アクセス URL の作成

1. 管理パネルから **アクセス URL** に移動します
2. **URL を追加** をクリックします
3. URL（例: `https://portal2.yoursite.com`）と説明を入力します
4. 任意で **親 URL** を選び、この URL を別の URL の下にネストできます — 下記の [URL 階層](#url-hierarchy) を参照してください
5. 保存します

### ユーザーとコースの割り当て

* **ユーザー** — ユーザーを特定のアクセス URL に割り当てます。1 人のユーザーは複数の URL に所属できます。
* **コース** — コースを特定のアクセス URL に割り当てます
* **セッション** — セッションを特定のアクセス URL に割り当てます

### URL ごとの設定

各アクセス URL は次の項目を独自に持てます。

* **カラーテーマ** — 異なる視覚的ブランディング
* **プラットフォーム名とロゴ** — 独自のアイデンティティ
* **設定の上書き** — 一部のプラットフォーム設定は URL ごとにカスタマイズできます

## URL 階層

アクセス URL は、フラットな一覧ではなく、親子のツリーとして整理できます。URL の作成または編集時、制限のないグローバル管理者（下記の [サブツリー管理者](#subtree-administrators) を参照）は、任意の他の URL を **親 URL** として選べます。

![親 URL のドロップダウンが開いた状態の URL 編集ダイアログ。親として選べる他のアクセス URL が一覧表示されている](/.gitbook/assets/admin-access-url-parent-select.png)

* ドロップダウンには、編集中の URL 自身、およびその子孫は親候補として表示されません。これにより循環が防げます。バックエンドは、画面表示にかかわらずこの制約を再検証します。
* 親を選ばずに URL を作成した場合、**ログイン専用 URL** が存在すればそれが既定になります（上記の [URL ごとの設定](#per-url-settings) を参照）。それ以外は最初のアクセス URL が既定になります。これは本機能導入前と同じ既定動作です。
* 親を持たないツリー最上位の URL が、そのツリーの **ルート** です。1 つの Chamilo インストールで、独立したツリーを複数ホストできます。

アクセス URL が一覧される場所（マルチ URL ダッシュボードおよびアクセス URL 管理ページ）では、ツリーはインデントで示され、親の直後にその子が続きます（兄弟はアルファベット順）。別途「親」列はありません。

![ルート URL と 2 つの子 URL、そのうち 1 つがさらに子 URL を持つ階層をインデントで示したアクセス URL 一覧](/.gitbook/assets/admin-access-url-hierarchy-list.png)

## サブツリー管理者

URL 階層は、[グローバル管理者](../users/user-roles.md) が管理できる範囲も決めます。

* ツリーの **ルート** URL に登録された管理者は **制限なし** です。導入前と同様、すべてのアクセス URL を管理します。
* **ルート以外** の URL にのみ登録された管理者は **スコープ付き** です。マルチ URL およびアクセス URL のページには、その URL とその子孫だけが表示され、マルチ URL ダッシュボードのログインチャートは「ログイン（すべての URL 合算）」ではなく「ログイン（担当 URL）」と表示されます。

スコープにかかわらず、次の操作は **制限なし** のグローバル管理者にのみ予約されています。スコープ付き管理者は、自身のサブツリー内の URL であっても実行できません。

* 新しいアクセス URL の作成
* アクセス URL 自身の URL、説明、または親の編集
* アクセス URL の有効化または無効化
* アクセス URL の削除（インストール全体のルート URL は、誰であっても削除できません）
* 自身をすべてのアクセス URL に一括登録すること

スコープ付き管理者は、サブツリー内の URL に *割り当てられた* もの（ユーザー、コース、セッション、ブランディング、設定）は引き続き管理できます。アクセス URL エントリそのものは管理できません。

## ヒント

* **早めに決定する** — マルチ URL 構成を選択する場合は、Chamilo プロジェクトの開始時点で行うべきです。最初の URL にはコンテンツをほとんど置かない必要があるためです。後からマルチ URL を有効化すると、より困難になります（データベースの手動変更が必要です）。
* **URL 構造を計画する** — アクセス URL を作成する前に URL スキームを決定してください。後から URL を変更すると、既存のリンクやブックマークすべてに影響します
* **DNS の設定** — 各アクセス URL は同一の Chamilo サーバーに解決されなければなりません。DNS レコードをそれに合わせて設定してください。
* **グローバル管理者** — すべてのアクセス URL を横断して管理するには、グローバル管理者ロールを使用します。1 つのブランチだけを委任して管理する場合は、ルート以外の URL に管理者を登録してください — [サブツリー管理者](#subtree-administrators) を参照
