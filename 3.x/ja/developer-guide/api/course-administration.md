# コース管理 API

Chamilo 3.1 では、管理者向けの連携が `Course` API リソースを通じてコースのメタデータを更新し、コースを削除できます。これらの操作は、ERP などの外部管理システムとの同期のために追加されました。

## 権限

| 操作 | メソッドとエンドポイント | 必要なロール |
|-----------|---------------------|---------------|
| コースの一覧 | `GET /api/courses` | 教師またはプラットフォーム管理者 |
| コースの表示 | `GET /api/courses/{id}` | そのコースを表示する権限 |
| コースの作成 | `POST /api/courses` | 教師またはプラットフォーム管理者 |
| コースの更新 | `PATCH /api/courses/{id}` | **プラットフォーム管理者（`ROLE_ADMIN`）** |
| コースの削除 | `DELETE /api/courses/{id}` | **プラットフォーム管理者（`ROLE_ADMIN`）** |

このリソースでは、`PUT` は操作として設定されていません。教師は引き続きコース設定画面から自身のコースを編集してください。新しい API の書き込み操作は管理者専用です。

必要な権限を持つ認証済みアカウント、または連携用の認証情報を使用してください。[API 認証](authentication.md) を参照してください。

## コースのメタデータを更新する

本文で指定したプロパティのみを変更するには、API Platform の JSON Merge Patch リクエストを送信します。

```http
PATCH /api/courses/42
Authorization: Bearer <admin-token>
Content-Type: application/merge-patch+json
Accept: application/ld+json
```

```json
{
  "title": "Introduction to Accounting - 2026"
}
```

このリクエストは新しいコースを作成するのではなく、既存のコースを更新します。API は、エンティティの検証に従い、`course:write` シリアライザグループで定義された書き込み可能なプロパティを受け付けます。例として、`title`、`visibility`、`categories`、`departmentUrl`、`videoUrl`、`sticky`、`duration` があります。`categories` などの関連プロパティには、API が想定するリソース表現が必要です。任意のデータベース ID を送信するのではなく、OpenAPI ドキュメントを確認してください。

**重要:** 内部のコース `code` は、この PATCH 操作では**書き込みできません**。`code` または `visualCode` フィールドを送信して、コースの内部コードの名前を変更しようとしないでください。

## コースを削除する

```http
DELETE /api/courses/42
Authorization: Bearer <admin-token>
```

これは**破壊的な**管理操作です。Chamilo は Doctrine エンティティを直接削除するのではなく、コース保守で使用されるのと同じコース削除ヘルパーを呼び出します。関連する登録、セッションおよびクラスのリンク、トラッキングデータ、ならびに該当する場合は関連する検索インデックスをクリーンアップします。

**マルチ URL** のインストールでは、削除によってコースがすべての場所から削除されるのではなく、現在のアクセス URL からの切り離しのみが行われる場合があります。コースのドキュメントは、保守画面の個別の *排他的ドキュメントの削除* オプションを使って削除されるわけではありません。API による削除を、すべてのドキュメントが物理的に削除されることの保証と解釈しないでください。

アクティブな依存関係が削除を妨げる場合（たとえばリソースのシーケンス）、エンドポイントは `409 Conflict` で応答することがあります。特にバッチ連携では、DELETE リクエストを送信する前にコースの依存関係とバックアップを確認してください。

## エラーと運用上の注意

* 必要な管理者ロールを持たない呼び出し元は拒否されます。PATCH または DELETE には、教師の認証情報ではなく、正しく認可されたアカウントを使用してください。
* 無効なリクエストデータは、エンティティの検証に失敗することがあります。パッチを適用する前に現在のコースを取得し、変更する意図のあるプロパティのみを送信してください。
* これらの操作は API Platform によって公開されています。正確なレスポンススキーマと受け付けるフィールド形式については、インストール済みインスタンスの OpenAPI ドキュメントを参照してください。
* コースの削除は、本番の学習者記録を含むコースではなく、使い捨て可能なコースでテストしてください。

画面でのコース管理については、[コースの管理](../../admin-guide/courses/managing-courses.md) を参照してください。セッションへの登録連携については、[セッションの受講者登録](session-students.md) を参照してください。
