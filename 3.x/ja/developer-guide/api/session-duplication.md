# セッションの複製

`POST /api/sessions/{id}/duplicate` は、既存の**モデルセッション**から新しいセッションを作成します。これは Chamilo 3 において、1.11.x の `webservices/api/v2.php` ウェブサービスの `create_session_from_model` アクションを置き換えるものであり、テンプレートセッションから新しい研修実施を開始する連携向けです。

## アクセス

| 呼び出し元 | 許可 |
|--------|---------|
| `ROLE_ADMIN` | 任意のセッション |
| `ROLE_SESSION_MANAGER` | 自身が管理するセッションのみ（モデルのセッション管理者である場合）。ただし、**セッション管理者にすべてのセッションの閲覧を許可する**設定が有効な場合を除く |
| それ以外 | `403 Forbidden` |

[認証](authentication.md) に記載のとおり、JWT または外部 API キーで認証します。

## リクエスト

```http
POST /api/sessions/42/duplicate
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
  "title": "Accounting basics - October 2026",
  "startDate": "2026-10-01T09:00:00+02:00",
  "endDate": "2026-12-15T18:00:00+01:00",
  "extraFields": { "my_session_field": "value" },
  "copySessionContent": false
}
```

| フィールド | 必須 | 説明 |
|-------|----------|-------------|
| `title` | はい | 新しいセッションのタイトル。他のセッションで既に使用されていないこと（最大 150 文字）。 |
| `startDate` | はい | ISO 8601 の日時。アクセス開始日、表示開始日、コーチのアクセス開始日として使用されます。 |
| `endDate` | はい | ISO 8601 の日時。`startDate` より前であってはなりません。アクセス終了日、表示終了日、コーチのアクセス終了日として使用されます。 |
| `extraFields` | いいえ | フィールドの変数をキーとするセッション追加フィールドの値。モデルからコピーされた値を上書きします。すべての変数は、既存のセッション追加フィールドでなければなりません。 |
| `copySessionContent` | いいえ | 既定は `false`。`true` の場合、各コースのセッション固有コンテンツ（文書、学習パス、テスト、カレンダーイベント、お知らせ、成績表など）が新しいセッションに複製されます。コースの基本コンテンツは常に共有され、コピーされることはありません。このフラグは、**セッション固有コンテンツを別のセッションへコピーする機能を有効にする**プラットフォーム設定とは独立しています。 |

## コピーされる内容

| モデルからコピーされるもの | コピーされないもの |
|-----------------------|------------|
| カテゴリ、公開状態、期間、説明、「説明を表示」 | コースコーチ |
| セッション追加フィールドの値 | 人事管理者（DRH） |
| コース（同じ順序） | 受講者 |
| 総合コーチ | |
| セッション管理者（モデルに存在しない場合、呼び出し元がセッション管理者になる） | |
| 「登録通知を送信する」オプション | |
| プロモーション | |
| セッション固有のコースコンテンツ（`copySessionContent` が `true` の場合のみ） | |

受講者は意図的に除外されます。各実施には独自の学習者が割り当てられます。後から `POST /api/course-sessions/actions/subscribe-users` で登録してください。

新しいセッションは、現在のアクセス URL に関連付けられます。

## レスポンス

`201 Created` と、新しいセッション:

```json
{
  "id": 57,
  "title": "Accounting basics - October 2026",
  "nbrCourses": 3,
  "visibility": 1,
  "generalCoachesSubscriptions": [{ "user": "/api/users/7" }]
}
```

## エラー

| ステータス | 発生条件 |
|--------|------|
| `401` | 資格情報がない、または無効 |
| `403` | 呼び出し元がモデルセッションを管理できない |
| `404` | モデルセッションが存在しない |
| `422` | フィールドの欠落または不正、`endDate` が `startDate` より前、タイトルが既に使用されている、または不明な追加フィールド変数 |

すべてのチェックは何も作成される前に実行されるため、拒否されたリクエストが不完全なセッションを残すことはありません。

## 実装

* 操作: `Session` リソース（`src/CoreBundle/Entity/Session.php`）上の `duplicate_session`
* 入力: `src/CoreBundle/Dto/SessionDuplicateInput.php`
* プロセッサ: `src/CoreBundle/State/Session/SessionDuplicateProcessor.php`。これは `SessionManager::copy()`（セッション一覧の**コピー**アクションでも使用）を呼び出し、その後、要求されたタイトル、日付、追加フィールド、ならびにモデルのプロモーション、セッション管理者、通知オプション、コース順序を適用します。
