# 使用者連線時間

`GET /api/users/{id}/connection-time` 會回傳使用者連線至平台的總時間。它取代 1.11.x `webservices/api/v2.php` 網路服務的 `get_user_total_connexion_time` 動作，並可限制於某一期間。

## 存取權限

| 呼叫者 | 允許 |
|--------|---------|
| `ROLE_ADMIN` | 目前存取 URL 的任何使用者 |
| 任何已驗證使用者 | 僅限其自身的連線時間 |
| 其他任何人 | `403 Forbidden` |

此端點接受使用者的數字 id。若要從使用者名稱開始，請先以 `GET /api/users?username=...` 查詢該使用者。

## 請求

```http
GET /api/users/42/connection-time?startDate=2026-10-01T00:00:00%2B02:00&endDate=2026-12-15T23:59:59%2B01:00
Authorization: Bearer <token>
```

| 查詢參數 | 必填 | 說明 |
|-----------------|----------|-------------|
| `startDate` | 否 | ISO 8601 日期時間。僅計入在此時間點或之後**開始**的連線。 |
| `endDate` | 否 | ISO 8601 日期時間，不得早於 `startDate`。僅計入在此時間點或之前**結束**的連線。 |

若未提供任一參數，則計入每一次連線。若僅提供 `startDate`，則自該日期起計入連線，沒有結束限制。若僅提供 `endDate`，則計入截至該日期的連線，沒有開始限制。

與邊界重疊的連線（例如在 `startDate` 之前開始的連線）完全不計入：連線時間絕不會被拆分。此規則與 1.11.x 報表的自訂期間篩選相同。

請包含時區偏移。在 URL 中，`+` 必須編碼為 `%2B`。沒有偏移的值會以伺服器的時區解讀。

## 回應

```json
{
  "id": 42,
  "username": "jdupont",
  "totalConnectionTime": 5025,
  "totalConnectionTimeFormatted": "01:23:45"
}
```

| 欄位 | 說明 |
|-------|-------------|
| `totalConnectionTime` | 以秒為單位的總計 |
| `totalConnectionTimeFormatted` | 相同總計，格式為 `HH:MM:SS`，亦即 1.11.x 網路服務所回傳的格式。小時數可以超過 24。 |

## 錯誤

| 狀態 | 時機 |
|--------|------|
| `400` | 無法剖析的日期，或 `endDate` 早於 `startDate` |
| `401` | 沒有憑證或憑證無效 |
| `403` | 呼叫者既非管理員，也非該使用者本人 |
| `404` | 使用者不存在，或不屬於目前的存取 URL |

## 時間的計算方式

總計為使用者在 `track_e_login` 資料表中各列的 `logout_date − login_date` 之和。

連線於登入時開始，並在使用者處於活動狀態時延長：使用者開啟的頁面在其分頁可見時，每分鐘會傳送一次在線訊號，如同 Chamilo 1.11.x 中每次頁面檢視的行為。若閒置時間超過工作階段存續時間，下一次活動會開啟新的連線，因此閒置間隔不計入。登出會關閉目前的連線。管理員使用 **Login as** 所花費的時間不會加到該使用者身上。

> **注意：** 在此追蹤功能恢復之前所記錄的連線可能沒有登出日期。它們計為零，因此升級前期間的總計可能低於實際花費的時間。
