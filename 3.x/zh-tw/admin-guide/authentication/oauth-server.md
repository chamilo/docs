# OAuth 2.1 授權伺服器與 MCP 用戶端

Chamilo 可作為 **OAuth 授權伺服器**，供連線至其受保護資源的用戶端使用。此功能與 [OAuth2 登入](oauth2.md) 不同；後者是 Chamilo 使用外部身分提供者讓使用者登入。

## 啟用與設定

在 **管理 > 組態設定 > 安全性** 下，啟用 `security.oauth_server_enabled`。MCP 存取亦取決於既有的 `security.mcp_enabled` 設定，以及使用者獲准的 MCP 角色。

伺服器會公開標準的授權、權杖、註冊與撤銷路由（`/oauth/authorize`、`/oauth/token`、`/oauth/register`、`/oauth/revoke`）以及探索中繼資料。正式環境的用戶端應僅使用 HTTPS。

## 註冊用戶端

Chamilo 支援公開的 PKCE 授權碼用戶端，以及已註冊的機密用戶端。動態用戶端註冊（DCR）使用 `/oauth/register`，並設有速率限制。`security.dynamic_client_registration` 設定**預設為停用**；該端點仍可供支援的 MCP 註冊流程使用，而此設定則控制註冊時可接受的額外用戶端範圍（scope）。請勿假設切換此設定即可使任意受保護的 API 可供使用。

已註冊的用戶端具有伺服器端的**允許資源**清單。目前資源登錄僅定義 **MCP** 資源與 `mcp` 範圍。新增受保護資源需要明確的伺服器實作與權限決策，而非僅在請求中加入無法識別的 URL。Chamilo 會在整個授權與權杖處理過程中驗證 RFC 8707 的 `resource` 參數。

## 使用者同意與稽核

1. 用戶端以 PKCE（`S256`）及所請求的範圍／資源，發起授權碼請求。
2. 如有必要，使用者以其一般的 Chamilo 登入進行驗證。
3. Chamilo 會在同意畫面顯示用戶端身分、註冊詳細資訊，以及所請求的存取權限。
4. 使用者選擇**允許**或**拒絕**。核准會記錄為伺服器同意歷程的一部分，後續請求可能會顯示先前的核准資訊。

同意僅綁定於向使用者顯示的該項請求。已核准的請求不會授予其他受保護資源，也不會授予超出所請求權限的任意存取。

## 部署與安全性注意事項

OAuth 2.1 更新為用戶端引入允許資源欄位，以及持久化的用戶端同意紀錄。在啟用更新後的流程之前，請先套用該版本所附的**特定 Chamilo 資料庫遷移**。請將回呼 URL 與 OAuth 用戶端密鑰保密。用戶端註冊並不會授予對 Chamilo 使用者或課程的不受限制存取。
