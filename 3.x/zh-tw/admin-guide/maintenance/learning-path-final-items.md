# 完成卡住的學習路徑最終項目

學習路徑的最後一步——包含證書與技能區塊的「恭喜」頁面——只有在學習者實際開啟後，才會被計為完成。若學習者已完成其他所有步驟，卻從未點進該最後一頁，進度便會永遠卡在略低於 100%；而成就證書資格（以及技能授予）取決於學習路徑達到 100%，因此他們無法取得原本已應得的證書或技能。

```bash
php bin/console chamilo:learning-path:complete-final-items [options]
```

對於平台上最後一步類型為 **Final item** 的每一條學習路徑，此指令會檢查每位進度未達 100%、嘗試仍在進行中、且已完成其他所有步驟的學習者——涵蓋重用該學習路徑的每一門課程與每一個會期。若符合條件，便會為其完成最終項目，效果等同於學習者親自開啟該頁：記錄相同的項目檢視、執行相同的進度重新計算，並觸發與實際造訪相同的證書產生與技能授予。

與 `chamilo:gradebook:process-achievement-certificates` 相同（請參閱
[成就證書](achievement-certificates.md)），此指令以有界批次運作、支援試運行，且中斷後可安全續跑——最終項目已完成的學習者，在後續執行中絕不會再次被處理。

## 選項

| Option                 | Purpose                                                                                                            |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `--dry-run`             | 評估並回報，但不完成任何項目。請一律先執行此選項。                                           |
| `--sender-id=<id>`      | 有效的平台管理員 ID，於完成最終項目而觸發證書產生或技能授予時，用作資源建立者。實際執行（非試運行）時為必填。 |
| `--limit=<n>`           | 單次執行中完成（或於試運行中回報）的最終項目數量上限。`0` = 無上限。預設為 `500`。              |
| `--scan-limit=<n>`      | 單次執行中掃描的學習者進度紀錄數量上限，涵蓋所有學習路徑。`0` = 無上限。預設為 `5000`。 |
| `--batch-size=<n>`      | 在單一學習路徑內，每一資料庫批次載入的學習者進度紀錄數量。預設為 `50`。                       |
| `--lp-batch-size=<n>`   | 每一資料庫批次載入的學習路徑數量。預設為 `50`。                                                            |
| `--after-lp-id=<id>`    | 從此學習路徑 ID 之後繼續掃描。                                                                       |

## 範例

先對整個平台進行試運行，以查看哪些學習者會被標為完成：

```bash
php bin/console chamilo:learning-path:complete-final-items --dry-run
```

實際執行，以 ID 為 1 的管理員作為資源建立者：

```bash
php bin/console chamilo:learning-path:complete-final-items --sender-id=1
```

在學習路徑 480 之後，續跑先前中斷的執行：

```bash
php bin/console chamilo:learning-path:complete-final-items --sender-id=1 --after-lp-id=480
```

## 結束代碼

若在實際執行期間至少有一個最終項目確實未能完成，此指令會以失敗狀態結束——摘要表會列出學習路徑、學習者與原因；應用程式日誌則包含完整例外。正確排除的學習者（最終項目已完成，或其他步驟仍未完成）並非錯誤，也絕不會導致失敗結束代碼。

## 完成後的成績簿分數

成績簿表格中顯示的學習路徑分數從不儲存——每次載入頁面時，皆依學習者目前進度即時計算，因此會立即反映 100%，無需額外步驟。

若學習者的**證書**在達到 100% 之前即已存在（其中已寫入較舊、較低的分數），則只有在此指令完成其最終項目、且證書重新產生本身成功時，儲存的分數與呈現的 HTML 才會更新——這與實際造訪所觸發的呼叫相同。若證書產生因任何原因失敗（常見原因請參閱
[成就證書](achievement-certificates.md)，例如檔案儲存權限），學習者進度仍會正確達到 100%，成績簿表格也仍會顯示該進度——僅其證書會繼續顯示舊分數；由於此指令絕不會再次處理已達 100% 的學習者，後續執行也不會重試。請在根本問題修正後，手動重新產生該證書（證書清單中的 **Generate** 動作）。

`--sender-id` 的存在，正是為了避免此失敗的一個常見原因：在真實請求之外完成最終項目時，沒有已登入使用者可供證書資源記錄為建立者，缺少建立者時產生會直接失敗。
