# BuyCourses：付款與週期性服務

**BuyCourses** 外掛程式可銷售課程與學習階段的存取權限，並可提供付費服務。可用的付款方式取決於安裝環境已設定的付款閘道。

## 付款設定

開啟 **管理 > 外掛程式 > BuyCourses**，並前往其付款設定區域。請在伺服器上維護閘道憑證，而非放在學習者可見的頁面。既有方式（例如 Stripe 與 PayPal）仍可獨立於 BTCPay Server 運作。

### BTCPay Server（課程與學習階段購買）

此外掛程式亦支援以 **BTCPay Server** 購買課程與學習階段：

1. 在 BuyCourses 設定中啟用 BTCPay 付款方式。
2. 設定 BTCPay 的 **Server URL**、**Store ID**、**Greenfield API key** 與 **webhook secret**。
3. 使用付款設定中的**連線測試**，確認可存取 Greenfield API。
4. 在 BTCPay 端設定 webhook，使用外掛程式顯示的 webhook URL 與相同的密鑰。
5. 在向學習者提供此選項之前，先完成一筆小額測試購買。

購買者會被重新導向至 BTCPay 託管的結帳頁面。Chamilo 會驗證 webhook 簽章，並再次擷取發票，以驗證**商店、金額、幣別與訂單明細**，之後才將訂單標示為已付款並為購買者註冊。瀏覽器返回可對帳遺漏或延遲的 webhook。重複通知不會產生重複履約。

僅已驗證且已結清的付款（包括已接受的超額付款，以及管理員明確標示為已結清的發票）才會授予存取權。**部分付款、逾期付款、已過期或無效的付款不得視為已自動履約**；例外付款須人工審核。

**既有安裝：** 請執行一次此外掛程式的更新程序，以建立 `plugin_buycourses_btcpay_account`。管理員可開啟 `/plugin/BuyCourses/update.php`，或儲存 BTCPay 付款設定（此動作亦會確保外掛程式資料表存在）。此更新僅適用於 BuyCourses，並非全域資料庫遷移。

此處**並未**將 BTCPay 記載為週期性服務閘道；請勿假設其實作了類似 Stripe／PayPal 的自動訂閱續約。

## 週期性服務生命週期

學習者可使用**我的服務**檢視其有效的週期性服務，以及購買／付款紀錄。對於支援自動續約的服務：

* 每一筆續約付款皆有各自的歷史紀錄與收據。
* 取消續約會阻止未來扣款，但已付費的服務在目前已付期間到期前仍可使用。
* 管理員亦可從**服務銷售報表**取消續約。
* 有效、待處理或其他仍在進行中的週期性訂閱，會受到保護以免重複購買。
* 已過期或已完全取消的服務可以再次購買。

**購買紀錄**與**付款紀錄**是分開的：單一次服務購買可能包含多筆續約付款。請勿將續約付款推斷為第二次購買。

## 服務銷售付款總額

在管理員的**服務銷售報表**中，有兩個欄位可協助區分原始訂單金額與隨時間收取的付款：

* **最近一次付款**顯示該筆服務銷售最近一次已記錄成功付款的日期。若沒有可用的付款日期，報表會顯示破折號。
* **已收取總額**顯示最初收取的購買金額，加上已記錄的成功續約金額，並以該服務的幣別格式化。它並不等於單一計費週期的價格。

計算使用服務銷售稽核紀錄，避免重複計算續約事件，並計入最初的 Stripe 訂閱扣款且不重複計算。對於例外付款或退款情況，請將報表與付款提供者對帳；所顯示的金額並非閘道撥款，也不是獨立的退款帳冊。

## 歷史 Stripe 訂閱

BuyCourses 可對帳較舊週期性服務的 Stripe 發票紀錄（其續約交易未完整記錄於外掛程式稽核日誌）。**我的服務**檢視與服務銷售報表可重新整理這些紀錄，並更新本機已知的已付期間與總額。管理員應針對例外的付款紀錄差異與 Stripe 核對，而非直接編輯銷售資料。

## 篩選銷售報表

**課程與學習階段銷售報表**可依訂單狀態、使用者、日期範圍或電子郵件篩選。選用的產品篩選可依產品類型與產品名稱縮小結果。**服務銷售報表**支援狀態篩選，以及使用者／電子郵件／姓名／訂單參考搜尋與服務名稱搜尋。在匯出或對帳銷售之前，請檢視目前啟用的篩選條件；兩個報表畫面的篩選控制項並不相同。

請參閱 [BuyCourses 銷售篩選 PR #9387](https://github.com/chamilo/chamilo-lms/pull/9387)。

## 訂閱關聯課程生命週期與刪除防護

BuyCourses 可在定期服務訂閱的付款狀態變更時，關閉、隱藏並重新啟用與之關聯的課程。在服務的 **Subscription behavior JSON** 中，`hide_after_days` 指定課程關閉後、隱藏前的延遲時間（預設為 30 天），而 `delete_after_days` 指定隱藏後、永久刪除前的延遲時間。刪除功能預設為停用（`null`）；僅正值才會使課程符合刪除資格。

管理員可於 `/admin/buycourses/course-lifecycle` 檢視符合資格、待處理與已封鎖的課程。此介面支援非破壞性模擬，以及在明確確認保護下，**每次執行僅針對一門符合資格的課程**進行刪除。CLI 處理器 `chamilo:buycourses:process-recurring-subscriptions` 亦支援 `--dry-run`、`--delete-expired` 與 `--max-deletions`（1–25）。若未加上 `--delete-expired`，則不會永久刪除課程。

**永久刪除具有破壞性。** 請先保留備份，並以可捨棄的課程進行測試。資格檢查會保護進行中的銷售、與會期關聯的課程，以及所有權不一致的情況；多存取 URL 安裝環境會封鎖自動刪除。在正式環境排程破壞性清理之前，請先檢視同時進行的續訂／刪除行為。請參閱 [訂閱課程生命週期 PR #9442](https://github.com/chamilo/chamilo-lms/pull/9442)。

## 營運檢查

升級後，請測試完整的課程購買、若有販售則測試會期購買、延遲／重送的 webhook、已過期與部分付款的 BTCPay 發票、自動續訂，以及取消後存取權持續至已付費期間結束的情況。請勿將憑證與 webhook 密鑰放入螢幕截圖、日誌與支援工單中。

## 付款強化

### 閘道金額檢查（Redsys / Cecabank）

當銀行通知平台付款成功時，BuyCourses 會將銀行收取的金額（以分為單位，來自已簽署的通知）與銷售價格進行比對。若兩者不一致，該通知會被拒絕，銷售維持待處理狀態，並在 PHP 錯誤日誌中寫入一行 `[BuyCourses] Redsys notification refused` 或 `[BuyCourses] Cecabank notification refused`。正常付款不受影響。

若買家已付款但銷售仍維持待處理，請檢查日誌：訂單建立後價格變更，或部分付款，都會顯示於此。經確認後，請從銷售報表手動完成該筆銷售。

### 安全性權杖

* 優惠券表單（新增／設定）、公開方案卡片表單，以及撥款動作，皆使用與其他外掛管理頁面相同的 BuyCourses 管理員權杖。表單長時間開啟時，只要工作階段仍然有效即可繼續使用；登出後再登入時，請先重新載入頁面再儲存（否則會顯示「Not validated」訊息）。
* 「索取發票」頁面（`request_invoice.php`）以及 `process_recurring_subscriptions.php` 的網頁觸發，必須在連結中包含權杖（`buycourses_admin_sec_token=...`）。已加入書籤或透過郵件傳送、但未包含權杖的連結會顯示「Not validated」。命令列／cron 執行方式（`php .../process_recurring_subscriptions.php` 或主控台命令）維持不變，且不需要權杖。
* 成功頁面（PayPal、Stripe、訂閱、服務）僅向購買該筆銷售的使用者顯示該銷售。
* 撥款動作（PayPal 大量付款、取消撥款）僅限平台管理員（不再接受會期管理員），且必須以 POST 方式並附帶權杖送出。

### 日期

訂閱銷售的結束日期現在一律以 UTC 計算，與銷售日期相同，不受伺服器時區影響。

### 多 URL 限制

服務到期時所套用的課程建立與託管限制，遵循與平台其餘部分相同的規則：在主要 URL 上已鎖定或標記為不可變更的設定，無法由其他 URL 覆寫。
