# URLs Πρόσβασης

Τα URLs πρόσβασης επιτρέπουν σε μία εγκατάσταση Chamilo να εξυπηρετεί πολλαπλές ξεχωριστές πύλες.

Το εργαλείο αυτό είναι επίσης προσβάσιμο από το μπλοκ [Πλατφόρμα](../platform/README.md) του πίνακα διαχείρισης, ως **Configure multiple access URL**.


## Περιπτώσεις Χρήσης

* **Αναπτύξεις πολλαπλών ενοικιαστών (multi-tenant)** — Φιλοξενία ξεχωριστών πυλών κατάρτισης για διαφορετικούς οργανισμούς σε έναν μόνο διακομιστή
* **Πύλες τμημάτων** — Παροχή σε κάθε τμήμα της δικής του πύλης με επωνυμία (π.χ. `hr.training.company.com`, `it.training.company.com`)
* **Περιφερειακές πύλες** — Ξεχωριστές πύλες για διαφορετικές περιοχές ή γλώσσες

## Πώς Λειτουργεί

Κάθε URL πρόσβασης αποτελεί ξεχωριστό σημείο εισόδου στην ίδια εγκατάσταση Chamilo:

* Οι χρήστες μπορούν να αντιστοιχιστούν σε ένα ή περισσότερα URLs πρόσβασης
* Τα μαθήματα και οι συνεδρίες ανήκουν σε συγκεκριμένα URLs πρόσβασης
* Οι ρυθμίσεις πλατφόρμας μπορούν να προσαρμοστούν ανά URL πρόσβασης
* Η επωνυμία και τα θέματα μπορούν να διαφέρουν ανά URL
* Οι χρήστες σε μία πύλη δεν μπορούν να δουν χρήστες ή μαθήματα σε άλλη (εκτός εάν έχουν κοινοποιηθεί ρητά)

## Διαμόρφωση

### Ενεργοποίηση Multi-URL

Το Multi-URL πρέπει να ενεργοποιηθεί στη διαμόρφωση του Chamilo (συνήθως στις ρυθμίσεις περιβάλλοντος). Αυτό γίνεται συνήθως κατά την αρχική εγκατάσταση.

### Δημιουργία URL Πρόσβασης

1. Από τον πίνακα διαχείρισης, μεταβείτε στα **Access URLs**
2. Κάντε κλικ στο **Add URL**
3. Εισαγάγετε το URL (π.χ. `https://portal2.yoursite.com`) και μια περιγραφή
4. Προαιρετικά επιλέξτε ένα **Parent URL** για να εμφωλεύσετε αυτό το URL κάτω από ένα άλλο — δείτε [Ιεραρχία URL](#url-hierarchy) παρακάτω
5. Αποθηκεύστε

### Αντιστοίχιση Χρηστών και Μαθημάτων

* **Χρήστες** — Αντιστοιχίστε χρήστες σε συγκεκριμένα URLs πρόσβασης. Ένας χρήστης μπορεί να ανήκει σε πολλαπλά URLs.
* **Μαθήματα** — Αντιστοιχίστε μαθήματα σε συγκεκριμένα URLs πρόσβασης
* **Συνεδρίες** — Αντιστοιχίστε συνεδρίες σε συγκεκριμένα URLs πρόσβασης

### Ρυθμίσεις ανά URL

Κάθε URL πρόσβασης μπορεί να έχει τα δικά του:

* **Θέμα χρωμάτων** — Διαφορετική οπτική επωνυμία
* **Όνομα πλατφόρμας και λογότυπο** — Προσαρμοσμένη ταυτότητα
* **Παρακάμψεις ρυθμίσεων** — Ορισμένες ρυθμίσεις πλατφόρμας μπορούν να προσαρμοστούν ανά URL

## Ιεραρχία URL

Τα URLs πρόσβασης μπορούν να οργανωθούν σε δέντρο γονέα/παιδιού αντί για επίπεδη λίστα. Κατά τη δημιουργία ή την επεξεργασία ενός URL, ένας μη περιορισμένος Καθολικός Διαχειριστής (δείτε [Διαχειριστές Υποδέντρου](#subtree-administrators) παρακάτω) μπορεί να επιλέξει οποιοδήποτε άλλο URL ως **Parent URL**:

![Παράθυρο διαλόγου επεξεργασίας URL με ανοιχτό το αναπτυσσόμενο μενού Parent URL, που παραθέτει τα άλλα URLs πρόσβασης διαθέσιμα ως γονέας](/.gitbook/assets/admin-access-url-parent-select.png)

* Το αναπτυσσόμενο μενού δεν προσφέρει ποτέ το URL που επεξεργάζεται, ούτε κανέναν από τους δικούς του απογόνους, ως πιθανό γονέα — αυτό αποτρέπει τη δημιουργία κύκλου. Το backend επανελέγχει αυτό ανεξάρτητα από ό,τι εμφανίζει η διεπαφή.
* Εάν ένα URL δημιουργηθεί χωρίς επιλογή γονέα, προεπιλέγεται το **login-only URL** εάν υπάρχει (δείτε [Ρυθμίσεις ανά URL](#per-url-settings) παραπάνω), διαφορετικά το πρώτο URL πρόσβασης — η ίδια προεπιλεγμένη συμπεριφορά όπως πριν από την ύπαρξη αυτής της λειτουργίας.
* Το ανώτατο URL ενός δέντρου — εκείνο χωρίς γονέα — είναι η **ρίζα** του δέντρου. Μία εγκατάσταση Chamilo μπορεί να φιλοξενεί περισσότερα από ένα ανεξάρτητα δέντρα.

Όπου παρατίθενται τα URLs πρόσβασης — ο πίνακας Multi-URL και η σελίδα διαχείρισης Access URLs — το δέντρο εμφανίζεται μέσω εσοχής, με έναν γονέα αμέσως ακολουθούμενο από τα δικά του παιδιά (τα αδέρφια ταξινομημένα αλφαβητικά), αντί για ξεχωριστή στήλη «Parent»:

![Λίστα URLs πρόσβασης που εμφανίζει ένα ριζικό URL με δύο θυγατρικά URLs, ένα εκ των οποίων έχει το δικό του θυγατρικό URL, με εσοχή ώστε να αποτυπώνεται η ιεραρχία](/.gitbook/assets/admin-access-url-hierarchy-list.png)

## Διαχειριστές Υποδέντρου

Η ιεραρχία URL καθορίζει επίσης τι μπορεί να διαχειριστεί ένας [Καθολικός Διαχειριστής](../users/user-roles.md):

* Όποιος είναι εγγεγραμμένος στο **ριζικό** URL ενός δέντρου είναι **μη περιορισμένος**: διαχειρίζεται κάθε URL πρόσβασης, ακριβώς όπως πριν από την ύπαρξη αυτής της λειτουργίας.
* Όποιος είναι εγγεγραμμένος μόνο σε ένα **μη ριζικό** URL είναι **περιορισμένος ως προς το εύρος**: οι σελίδες Multi-URL και Access URLs εμφανίζουν μόνο εκείνο το URL και τους απογόνους του, και το γράφημα συνδέσεων στον πίνακα Multi-URL αναγράφει «Logins (your URLs)» αντί για «Logins (all URLs combined)».

Ανεξάρτητα από το εύρος, τα ακόλουθα παραμένουν αποκλειστικά για έναν **μη περιορισμένο** Καθολικό Διαχειριστή — ένας περιορισμένος διαχειριστής δεν μπορεί να τα εκτελέσει ούτε για URLs εντός του δικού του υποδέντρου:

* Δημιουργία νέου URL πρόσβασης
* Επεξεργασία του ίδιου του URL, της περιγραφής ή του γονέα ενός URL πρόσβασης
* Ενεργοποίηση ή απενεργοποίηση ενός URL πρόσβασης
* Διαγραφή ενός URL πρόσβασης (το ριζικό URL ολόκληρης της εγκατάστασης δεν μπορεί ποτέ να διαγραφεί, από κανέναν)
* Εγγραφή του εαυτού τους σε κάθε URL πρόσβασης ταυτόχρονα

Ένας περιορισμένος διαχειριστής μπορεί ακόμη να διαχειρίζεται όλα όσα *έχουν αντιστοιχιστεί* στα URLs του υποδέντρου του — χρήστες, μαθήματα, συνεδρίες, επωνυμία και ρυθμίσεις — απλώς όχι τις ίδιες τις εγγραφές των URLs πρόσβασης.

## Συμβουλές

* **Αποφασίστε έγκαιρα** — Αν επιλέξετε ρύθμιση πολλαπλών URL, θα πρέπει να το κάνετε στην αρχή του έργου Chamilo, καθώς απαιτείται το πρώτο URL να παραμείνει σχετικά κενό από περιεχόμενο. Η ενεργοποίηση πολλαπλών URL εκ των υστέρων είναι πιο απαιτητική (απαιτεί χειροκίνητες αλλαγές στις βάσεις δεδομένων).
* **Σχεδιάστε τη δομή των URL** — Αποφασίστε το σχήμα των URL πριν δημιουργήσετε τα access URL, καθώς η αλλαγή των URL αργότερα επηρεάζει όλους τους υπάρχοντες συνδέσμους και σελιδοδείκτες
* **Ρύθμιση DNS** — Κάθε access URL πρέπει να επιλύεται στον ίδιο διακομιστή Chamilo. Ρυθμίστε τα αντίστοιχα αρχεία DNS.
* **Καθολικός διαχειριστής** — Χρησιμοποιήστε τον ρόλο Global Administrator για διαχείριση σε όλα τα access URL. Για να αναθέσετε τη διαχείριση μόνο ενός κλάδου, καταχωρίστε τον διαχειριστή σε ένα μη ριζικό URL — δείτε [Διαχειριστές υποδέντρου](#subtree-administrators)
