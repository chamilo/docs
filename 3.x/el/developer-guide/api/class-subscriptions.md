# API συμμετοχής και εγγραφής σε τάξη

Για ενσωματώσεις, το Chamilo παρέχει endpoints για την ανάγνωση και τον συγχρονισμό των μελών, των συνεδριών και των μαθημάτων που σχετίζονται με μια υπάρχουσα **τάξη**. Μια τάξη είναι ένα `Usergroup` τύπου *normal class*· αυτές οι διαδρομές **δεν** εφαρμόζονται σε κοινωνικές ομάδες.

Σε αντίθεση με το API φοιτητών συνεδρίας, οι τρεις ενέργειες `PUT` της τάξης **αντικαθιστούν ολόκληρη την καθορισμένη λίστα**. Τα παραλειπόμενα αναγνωριστικά αφαιρούνται από τη συγκεκριμένη σχέση. Διαβάστε την υπάρχουσα λίστα πριν την ενημερώσετε και αποφύγετε τη χρήση του `PUT` για την προσθήκη ενός μόνο μέλους, εκτός αν υποβάλετε επίσης όλους όσους πρέπει να παραμείνουν.

## Εξουσιοδότηση

Όλες οι παρακάτω διαδρομές απαιτούν τον αυθεντικοποιημένο ρόλο πλατφόρμας `ROLE_ADMIN`. Η τάξη-στόχος πρέπει να είναι διαθέσιμη στο τρέχον URL πρόσβασης. Μια τάξη που λείπει ή βρίσκεται εκτός εμβέλειας επιστρέφει `404`· ένα usergroup που δεν είναι κανονική τάξη επιστρέφει `409 Conflict`.

Ο controller ελέγχει ότι τα υποβληθέντα αναγνωριστικά χρηστών, μαθημάτων και συνεδριών υπάρχουν. Σε εγκατάσταση πολλαπλών URL, τα υποβληθέντα **αναγνωριστικά μαθημάτων και συνεδριών** φιλτράρονται στην τρέχουσα πύλη· ωστόσο, η τρέχουσα υλοποίηση **δεν** εφαρμόζει το ίδιο φίλτρο πύλης στα **αναγνωριστικά χρηστών**. Οι ολοκληρωτές δεν πρέπει να αντιμετωπίζουν αυτό το endpoint ως εγγύηση απομόνωσης σε επίπεδο χρήστη ανά πύλη. Δείτε τις σημειώσεις ανασκόπησης παράδοσης για αυτή την εκκρεμή παράμετρο ασφαλείας.

## Ανάγνωση σχέσεων τάξης

```http
GET /api/usergroups/31/subscriptions
Authorization: Bearer <admin-token>
```

Παράδειγμα απόκρισης:

```json
{
  "userIds": [17, 23],
  "sessionIds": [42],
  "courseIds": [8, 11]
}
```

## Αντικατάσταση μίας λίστας σχέσεων

| Μέθοδος | Endpoint | Ιδιότητα αιτήματος |
|--------|----------|------------------|
| `PUT` | `/api/usergroups/{id}/users` | `userIds` |
| `PUT` | `/api/usergroups/{id}/sessions` | `sessionIds` |
| `PUT` | `/api/usergroups/{id}/courses` | `courseIds` |

Για παράδειγμα, για να ορίσετε την πλήρη κατάσταση μελών της τάξης:

```http
PUT /api/usergroups/31/users
Authorization: Bearer <admin-token>
Content-Type: application/json
```

```json
{ "userIds": [17, 23, 29] }
```

Παράδειγμα απόκρισης:

```json
{
  "success": true,
  "applied": [17, 23, 29],
  "ignored": []
}
```

Το `applied` παραθέτει τα αποδεκτά αναγνωριστικά, όχι απαραίτητα τα νεοπροστεθέντα. Το `ignored` προσδιορίζει τα ζητηθέντα αναγνωριστικά που δεν μπόρεσαν να εφαρμοστούν (για παράδειγμα, άγνωστο αναγνωριστικό ή μάθημα/συνεδρία εκτός της τρέχουσας πύλης). Οι μη θετικές τιμές παραλείπονται, τα διπλότυπα αφαιρούνται, και κακοσχηματισμένο JSON ή ιδιότητα αιτήματος που δεν είναι πίνακας επιστρέφει `400`.

Για να αντικαταστήσετε αντ' αυτού τις συνδεδεμένες συνεδρίες, καλέστε το `PUT /api/usergroups/31/sessions` με `{ "sessionIds": [42, 57] }`. Για να αντικαταστήσετε τα συνδεδεμένα μαθήματα, καλέστε το `PUT /api/usergroups/31/courses` με `{ "courseIds": [8, 11] }`.

**Σημαντικό:** Το Chamilo εφαρμόζει αυτές τις αλλαγές μέσω των μεθόδων συγχρονισμού του `UsergroupHelper`. Η αλλαγή της κατάστασης μελών της τάξης ή των δεσμεύσεών της με συνεδρίες/μαθήματα μπορεί επίσης να αλλάξει σχετικές εγγραφές. Μην χειρίζεστε απευθείας τους πίνακες σχέσεων usergroup και εξετάστε το αποτέλεσμα της αντικατάστασης λιστών πριν εκτελέσετε μια ενσωμάτωση σε παραγωγή.

Για τη διεπαφή και την έννοια, δείτε [Τάξεις](../../admin-guide/sessions/classes.md). Για να προσθέσετε ή να αφαιρέσετε συγκεκριμένους εκπαιδευόμενους από μία συνεδρία *χωρίς* να αντικαταστήσετε όλα τα μέλη, χρησιμοποιήστε το [API εγγραφής φοιτητών συνεδρίας](session-students.md).
