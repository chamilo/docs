# API εγγραφής εκπαιδευομένων σε συνεδρία

Οι ενσωματώσεις μπορούν να εμφανίζουν, να εγγράφουν και να αφαιρούν εκπαιδευόμενους σε μια συνεδρία μέσω τερματικών σημείων αποκλειστικά για διαχειριστές. Οι ενέργειες αυτές χρησιμοποιούν τη συμπεριφορά εγγραφής σε συνεδρία των οθονών διαχείρισης του Chamilo. Είναι διακριτές από το `/api/course-sessions/actions/*`, το οποίο ανήκει σε διαφορετική ροή εργασίας προσανατολισμένη στους διδάσκοντες.

## Έλεγχος ταυτότητας και πρόσβαση

Κάθε λειτουργία παρακάτω απαιτεί έλεγχο ταυτότητας με τον ρόλο πλατφόρμας `ROLE_ADMIN`. Η ιδιότητα του διαχειριστή συνεδρίας από μόνη της **δεν** παρέχει πρόσβαση. Χρησιμοποιήστε τη μέθοδο ελέγχου ταυτότητας που περιγράφεται στο [Έλεγχος ταυτότητας](authentication.md).

Σε εγκαταστάσεις πολλαπλών URL, η ζητούμενη συνεδρία πρέπει να ανήκει στο τρέχον URL πρόσβασης· διαφορετικά το τερματικό σημείο απαντά με `404`.

## Διαδρομές

| Μέθοδος | Τερματικό σημείο | Σκοπός |
|--------|----------|---------|
| `GET` | `/api/sessions/{id}/students` | Εμφάνιση των αναγνωριστικών χρηστών των εκπαιδευομένων που είναι εγγεγραμμένοι σε αυτή τη συνεδρία |
| `POST` | `/api/sessions/{id}/students/subscribe` | Προσθήκη των καθορισμένων εκπαιδευομένων, διατηρώντας τους υπάρχοντες εκπαιδευόμενους |
| `POST` | `/api/sessions/{id}/students/unsubscribe` | Αφαίρεση μόνο των καθορισμένων εκπαιδευομένων |

Αντικαταστήστε το `{id}` με το αριθμητικό αναγνωριστικό της συνεδρίας. Και για τα δύο αιτήματα POST, στείλτε JSON που περιέχει τον πίνακα `userIds`:

```http
POST /api/sessions/42/students/subscribe
Authorization: Bearer <admin-token>
Content-Type: application/json
```

```json
{ "userIds": [17, 23] }
```

Μια επιτυχής εγγραφή παράγει απόκριση με την ακόλουθη δομή· τα αναγνωριστικά εξαρτώνται από την εγκατάστασή σας:

```json
{
  "success": true,
  "applied": [17],
  "alreadyThere": [23],
  "ignored": []
}
```

Το `applied` περιέχει τους νεοεγγεγραμμένους εκπαιδευόμενους· το `alreadyThere` περιέχει εκπαιδευόμενους που είναι ήδη εγγεγραμμένοι· το `ignored` παραθέτει μη επιλέξιμα ή μη διαθέσιμα αναγνωριστικά. Κατά την εγγραφή, το Chamilo εγγράφει επίσης τους προστιθέμενους εκπαιδευόμενους στα μαθήματα της συνεδρίας. **Δεν** αντικαθιστά ολόκληρο τον κατάλογο της συνεδρίας.

Για επιθεώρηση της συμμετοχής:

```http
GET /api/sessions/42/students
Authorization: Bearer <admin-token>
```

```json
{ "userIds": [17, 23] }
```

Για αφαίρεση επιλεγμένων εκπαιδευομένων:

```http
POST /api/sessions/42/students/unsubscribe
Authorization: Bearer <admin-token>
Content-Type: application/json
```

```json
{ "userIds": [17] }
```

Η απόκριση κατάργησης εγγραφής περιέχει τα `success`, `applied` (αφαιρεθέντα αναγνωριστικά) και `ignored` (αναγνωριστικά που δεν είναι εγγεγραμμένα). Οι υπόλοιποι εκπαιδευόμενοι παραμένουν στη συνεδρία.

## Επικύρωση και περιορισμοί

* Το `userIds` πρέπει να είναι πίνακας αριθμητικών αναγνωριστικών (ακέραιοι ή συμβολοσειρές μόνο με ψηφία). Τα επαναλαμβανόμενα αναγνωριστικά αποδιπλασιάζονται· οι μη θετικές τιμές παραλείπονται.
* Για την εγγραφή, οι επιλέξιμοι χρήστες πρέπει να υπάρχουν, να μην έχουν διαγραφεί ήπια, να μην είναι ανώνυμοι ή υπεύθυνοι ανθρώπινου δυναμικού, και να ανήκουν στο τρέχον URL πρόσβασης.
* Ελλιπές ή κακοσχηματισμένο JSON ή `userIds` επιστρέφει `400 Bad Request`.
* Ανύπαρκτες ή εκτός εμβέλειας συνεδρίες επιστρέφουν `404 Not Found`· οι καλούντες χωρίς δικαίωμα διαχειριστή δεν μπορούν να χρησιμοποιήσουν αυτές τις διαδρομές.
* Οι διαδρομές εγγραφής εκπαιδευομένων **δεν** είναι γενικά τερματικά σημεία CRUD για την οντότητα `Session` και δεν δέχονται κατάλογο συνεδρίας ως έγγραφο αντικατάστασης.

Για την αντίστοιχη διεπαφή διαχείρισης, δείτε τη [Διαχείριση συνεδριών](../../admin-guide/sessions/managing-sessions.md). Για την αντιγραφή μιας πρότυπης συνεδρίας πριν από την εγγραφή εκπαιδευομένων, δείτε την [Αντιγραφή συνεδρίας](session-duplication.md).
